# 输入/输出系统

输入/输出系统把主机与外部设备连接起来，使程序能够取得外部信息并输出处理结果。麻烦在于两端的节奏相差极大：键盘按人的手速送来字符，磁盘和网卡要连续搬运成批数据，而 CPU 以纳秒计时，停下来等一个字符的时间足够它执行上百万条指令。于是，每次传送都要先回答几个问题——由谁发起，数据由谁搬运，CPU 又在什么时候抽身去做别的事。

## I/O系统基本概念\*

### 输入/输出系统\*

从主机的角度看，**输入** 是信息从外部设备进入主机，**输出** 是信息从主机送往外部设备。输入/输出系统通过设备、控制器和软件建立通路，安排请求、数据交换与完成通知。

<center class="centered-table" markdown="1">

| 组成 | 主要内容 | 作用 |
| --- | --- | --- |
| I/O 硬件 | 外部设备、设备控制器、I/O 接口、总线等 | 提供设备操作与信息交换的物理基础 |
| I/O 软件 | 应用程序、设备驱动程序、I/O 管理程序等 | 发出请求、设置控制参数、处理状态与完成结果 |

</center>

外部设备包括输入设备、输出设备和通过 I/O 通路访问的外部存储设备。接口面向主机的信息交换，控制器还承担设备的具体控制；这些功能可以集成在同一硬件部件中，接口的详细功能见 [I/O 接口](#io接口)。

### 外部设备\*

#### 输入设备

-   **键盘** 输入字符、数字和控制命令。
-   **鼠标** 将用户的定位与选择操作转换为计算机可识别的信息。

#### 输出设备

显示器以像素阵列呈现图像。常见显示技术涉及 CRT、液晶和发光二极管等，分析显示数据量时，主要关注以下参数：

<center class="centered-table" markdown="1">

| 参数 | 含义 |
| --- | --- |
| 屏幕尺寸 | 通常以屏幕对角线长度表示 |
| 分辨率 | 一帧包含的横向、纵向像素数，例如 $W\times H$ |
| 色彩深度 | 每像素编码位数 $b$；8 位可表示 256 级，24 位可表示约 1677 万种颜色 |
| 刷新频率／帧频 | 每秒输出或刷新图像的次数 $r$ |
| 显示存储器 VRAM | 保存显示图像数据的存储空间 |

</center>

在按像素连续保存、一帧不压缩的模型中：

$$
C_{\mathrm{frame}}=WHb\quad(\mathrm{bit}),
\qquad C_{\mathrm{frame}}=\frac{WHb}{8}\quad(\mathrm{B}).
$$

每次刷新读取一帧时，刷新所需的数据带宽为：

$$
B_{\mathrm{refresh}}=\frac{WHbr}{8}\quad(\mathrm{B/s}).
$$

如果显存总带宽中只有比例 $\alpha$ 可用于刷新，则需满足 $B_{\mathrm{total}}\geq B_{\mathrm{refresh}}/\alpha$。单帧容量由像素数和每像素位数决定，刷新带宽再乘每秒刷新次数。

打印机按工作原理可以分为：

<center class="centered-table" markdown="1">

| 类型 | 工作原理 | 典型特点 |
| --- | --- | --- |
| 针式打印机 | 打印针撞击色带形成点阵 | 可多层复写，但噪声大、分辨率和速度较低 |
| 喷墨打印机 | 喷射微小墨滴，用青、品红、黄等墨色混合形成图像 | 适合彩色输出 |
| 激光打印机 | 激光扫描结合静电成像、显影、转印和定影 | 输出速度与质量较高 |

</center>

#### 外部存储器

磁表面存储器利用磁化状态保存信息，代表有硬盘、软盘、磁带和磁鼓；SSD 通常使用 Flash。它们通过控制器与主机交换数据，介质及组织方式见[磁盘存储器](storage.md#磁盘存储器)和[固态硬盘](storage.md#固态硬盘)。

光盘通过聚焦激光束以非接触方式读写信息。一个光盘系统包括盘片、驱动器和控制器，常见介质类型有 CD、DVD 等。

## I/O接口

**I/O 接口**，也称 I/O 控制器，是主机与外部设备交换信息的交接部件。设备的速度、数据格式和电气信号各不相同，接口需要把这些差异转换为主机可控制的访问过程。

### I/O接口的功能

<center class="centered-table" markdown="1">

| 功能 | 要解决的问题 |
| --- | --- |
| 地址译码与设备选择 | 判断本次访问是否选中本接口及其中哪个寄存器 |
| 通信联络与时序协调 | 用状态或握手信息协调主机与设备的操作节奏 |
| 数据缓冲 | 暂存正在交换的数据，缓解双方速度差异 |
| 信号与格式转换 | 按设备需要完成电平、串并行或其他格式转换 |
| 命令与状态传递 | 接收主机的控制命令，报告就绪、忙、错误等状态，按需要发出中断请求 |

</center>

接口按设备需要设置相应电路。例如，串行设备需要串并转换，速度不匹配时需要缓冲；设备就绪后还可通过[中断请求](#程序中断方式)通知 CPU。

### I/O接口的基本结构

主机侧通过总线访问接口，设备侧通过相应信号与外设连接。基本结构包括数据、状态和控制寄存器，以及地址译码和 I/O 控制逻辑。

<center class="centered-table" markdown="1">

| 部件 | 保存或执行的内容 | 基本访问方式 |
| --- | --- | --- |
| 数据缓冲寄存器 | 从设备取得或准备送给设备的数据 | CPU 按输入、输出方向读或写 |
| 状态寄存器 | 就绪、忙、完成、错误等状态 | 基本模型中由 CPU 读取 |
| 控制寄存器 | 启动、停止、传送方向等控制命令字 | 基本模型中由 CPU 写入 |
| 地址译码逻辑 | 识别接口和内部端口地址 | 根据地址选择目标 |
| I/O 控制逻辑 | 解释命令、控制缓冲器传送、采集设备状态 | 协调主机侧与设备侧操作 |

</center>

在一些设计中，状态与控制寄存器可以使用同一个端口地址：读时选中状态寄存器，写时选中控制寄存器。**地址与读写方向共同选择寄存器**。

主机侧的三组信号各有分工：

-   **数据线** 传送数据、状态字、控制命令字，以及某些向量中断模型中的中断类型号。
-   **地址线** 选择要访问的接口端口。
-   **控制线** 表明读写操作，并传送中断请求、响应或总线控制等信号。

命令字作为编码值经数据线写入控制寄存器，控制线上的“写使能”表明本次执行写操作。两类信息分别对应[数据线与控制线](bus.md#总线的分类)。

### I/O接口的类型

<center class="centered-table" markdown="1">

| 分类角度 | 类型 | 说明 |
| --- | --- | --- |
| 外设与接口一侧的数据传送 | 串行接口、并行接口 | 按位依次传送，或多位同时传送 |
| 主机组织传送的控制方式 | 查询接口、中断接口、DMA 接口 | 按不同方式报告状态并完成交换 |
| 功能能否通过程序配置 | 可编程接口、不可编程接口 | 能否通过控制字等改变工作模式 |

</center>

串行接口可以先把设备逐位传入的数据组装成字节或字，再通过主机侧的数据端口一次读出；输出时执行反向转换。

### I/O端口及其编址

**I/O 端口** 是接口内部可被 CPU 寻址访问的寄存器，如数据端口、状态端口和控制端口。一个接口可以有多个端口，**端口是可访问的位置，接口是包含这些位置及控制逻辑的部件**。

#### 独立编址

独立编址，也称 I/O 映射方式，为端口设置与主存分开的地址空间。相同数值可以分别表示一个主存地址和一个端口号，由访问指令及相应控制信号区分。

CPU 使用专用 I/O 指令访问，例如 `IN`、`OUT`。这种方式不占用主存地址空间，I/O 操作易于识别，端口地址译码通常较简单；代价是需要专用指令及控制，可用的 I/O 操作形式受到指令集限制。

#### 统一编址

统一编址，也称 **存储器映射 I/O**（Memory-Mapped I/O，MMIO），把统一地址空间的一部分分配给 I/O 端口。CPU 通过普通加载、存储等指令访问端口，地址译码决定目标是主存还是设备。

统一编址可以复用普通访存指令和寻址形式，也便于结合存储保护机制。地址空间中分给 I/O 的范围用于选择设备寄存器；在受限地址空间内，可直接分配给 RAM 的地址范围相应减少。

<center class="centered-table" markdown="1">

| 对比项 | 独立编址 | 统一编址 |
| --- | --- | --- |
| 地址空间 | I/O 与主存分开 | I/O 与主存共用 |
| 访问指令 | 专用 I/O 指令 | 普通访存指令 |
| 主存地址范围 | 不被 I/O 端口占用 | 部分范围分配给 I/O |
| 控制与译码 | 区分存储器访问和 I/O 访问 | 按统一地址范围选择目标 |
| 编程特点 | 操作清晰，但指令形式通常较少 | 可利用已有访存与寻址能力 |

</center>

两种编址方式都通过相应权限机制控制设备访问。独立编址可以限制 I/O 指令，MMIO 则可以通过地址映射与存储保护控制哪些程序能访问设备寄存器，相关基础见[特权模式](../OS/os_intro.md#priv)。

## I/O方式

主机与外设交换数据时，需要决定何时传送、由谁搬运、怎样报告完成。下面三种方式的差别集中在这些控制环节。

### 程序查询方式

#### 查询与数据传送流程

**程序查询方式** 由 CPU 执行程序读取设备状态，确认就绪后再执行数据传送指令。一次输入可以按以下步骤组织：

1.  初始化主存起始地址、数据数量等参数，并向接口发送启动命令。
2.  读取状态端口；未就绪时继续等待或稍后重查。
3.  就绪后从数据端口读取数据，写入主存。
4.  修改主存地址与计数，若尚未传完，返回状态检查。

输出时的数据方向相反：CPU 确认设备能够接收后，把主存中的数据写入数据端口。

查询策略可以分为：

<center class="centered-table" markdown="1">

| 策略 | CPU 的工作方式 | 特点 |
| --- | --- | --- |
| 独占查询 | 启动设备后不断读取状态，直到操作完成 | 忙等待占用 CPU，不能在等待期间执行其他程序工作 |
| 定时查询 | 按一定间隔检查，检查之间继续执行其他工作 | 能与设备准备过程重叠，但必须及时取走或送入数据 |

</center>

查询方式的硬件与控制较简单，状态检查和数据搬运都由 CPU 完成。独占查询占用整个等待时段，定时查询则只在检查与搬运期间占用 CPU，开销由查询频率和每次指令量决定。

#### 查询间隔与CPU开销

假定设备持续产生数据、速率为 $R\mathrm{B/s}$，缓冲寄存器一次容纳 $g\mathrm{B}$，CPU 每次取走这一份数据。在该单缓冲模型中，为避免覆盖未处理数据，查询及处理间隔应满足：

$$
\Delta t\leq\frac{g}{R},
\qquad f_{\mathrm{poll}}\geq\frac{R}{g}.
$$

一次查询及相应处理若执行 $I$ 条指令、平均 CPI 为 $c$，就占用 $Ic$ 个 CPU 时钟周期。CPU 主频为 $f$ 时，这些操作所占的 CPU 时间比例为：

$$
U_{\mathrm{poll}}=\frac{f_{\mathrm{poll}}Ic}{f}.
$$

!!! example "查询频率与 CPU 时间开销"

    例如，$R=2\mathrm{MB/s}$，缓冲寄存器为 32 位，即 $g=4\mathrm{B}$；$f=500\mathrm{MHz}$，每次查询执行 10 条指令，CPI 为 4，则：

    $$
    \Delta t_{\max}=\frac{4}{2\times10^6}=2\mu\mathrm{s},
    \qquad f_{\mathrm{poll,min}}=5\times10^5\mathrm{/s},
    $$

    $$
    U_{\mathrm{poll,min}}=
    \frac{5\times10^5\times10\times4}{500\times10^6}=4\%.
    $$

以最大允许间隔查询时，查询频率与相应开销最低。更频繁的查询会增加 CPU 时间占比，数据搬运等额外指令也会增加每次服务的开销。本章速率中的 MB/s 采用 $10^6\mathrm{B/s}$。

### 程序中断方式

#### 基本思想与已有知识

**程序中断方式** 让设备在需要服务时主动通知 CPU。CPU 启动设备后可继续执行其他工作；设备准备就绪后发出请求，CPU 通过中断服务程序完成所需的数据传送，再恢复被打断的程序。

本节讨论 **可屏蔽 I/O 中断**。设备准备与 CPU 的其他工作可以重叠，逐次数据搬运仍由 CPU 执行服务程序完成。服务结束后恢复被打断程序的执行；发起 I/O 的进程若已阻塞，则由操作系统在合适时机重新调度。

从事件角度看，I/O 中断来自设备，是异步事件；缺页、非法指令等[异常](CPU.md#异常和中断的基本概念)通常来自当前指令执行。CPU 先通过硬件响应进入服务程序，再由软件完成设备操作。

#### 中断请求与响应判优

**中断源** 是发出请求的设备或事件。为了记录异步到来的请求，可为每个源设置请求标记触发器；置 1 表示该源存在待处理请求，多个标记可组成请求寄存器。

设备的请求是否能够参与判优，还要结合设备侧中断允许状态和屏蔽位。在“1 为屏蔽、0 为允许”的模型中，第 $i$ 个源可参与判优的条件为：

$$
\mathrm{Eligible}_i=
\mathrm{Request}_i\land\mathrm{Enable}_i\land\lnot\mathrm{Mask}_i.
$$

多个有效请求同时存在时，判优逻辑选择先响应哪一个。硬件排队电路可以完成这种选择，软件查询顺序也可以形成相应优先级。选择时常考虑设备速度和实时性等要求，而非仅按设备编号大小。

需要区分 **响应优先级与处理优先级**：

<center class="centered-table" markdown="1">

| 概念 | 决定的事情 | 本章基本模型 |
| --- | --- | --- |
| 响应优先级 | 多个未屏蔽请求同时等待时，先选择哪个源 | 由硬件判优次序或查询次序决定 |
| 处理优先级 | 处理中断时，允许哪些新请求抢占当前服务 | 通过服务程序装入的屏蔽字安排嵌套关系 |

</center>

固定判优次序决定候选请求之间的选择顺序，屏蔽字决定哪些源能进入候选集合。实际的嵌套次序还取决于请求到达、装入屏蔽字、开中断和返回等事件发生的时刻。

#### CPU响应I/O中断的条件

对本节的可屏蔽外部中断，CPU 响应需要同时满足：

1.  存在已允许、未屏蔽的有效请求。
2.  CPU 处于开中断状态。
3.  到达可响应的指令边界，且当前请求被判优逻辑选中。

设备就绪后，经设备侧允许、请求锁存、源屏蔽和 CPU 全局允许等环节，才可能在指令边界进入响应。上述条件用于可屏蔽 I/O 中断，[异常与不可屏蔽中断](CPU.md#异常和中断的分类)按各自规则处理。

!!! question "开中断后，一有请求就立即响应吗？"

    在基本模型中，CPU 在可响应的指令边界采样请求。若此时已开中断，存在未屏蔽的有效请求且被判优选中，就进入硬件响应。请求若在指令执行中到达，则先等待这个边界，具体条件见[响应条件](#cpu响应io中断的条件)。

#### 硬件响应与软件处理

CPU 先由硬件暂时关中断，保存返回地址与必要的处理器状态，再取得服务程序入口并更新 PC。这组硬件动作称为 **中断隐指令**，由硬件自动组织。其具体过程见[异常和中断的响应过程](CPU.md#异常和中断的响应过程)。

传统向量中断模型中，请求与响应信号经控制线传送，中断控制器在响应阶段经数据线提供类型号。CPU 用类型号定位向量表项，再取得服务程序入口。

[识别事件并转入处理程序](CPU.md#识别事件并转入处理程序)这一节已经讲了向量中断、中断向量和向量地址的区别，这里不再重复。

完成硬件响应后，支持嵌套的服务程序通常还要组织以下软件步骤：

<center class="centered-table" markdown="1">

| 阶段 | 软件操作 | 目的 |
| --- | --- | --- |
| 进入服务程序 | 保存将被改写的寄存器和原屏蔽字，装入本层屏蔽字 | 保护现场，并设定允许抢占当前服务的请求 |
| 允许嵌套 | 在关键保存完成后开中断 | 让符合屏蔽规则的更高处理优先级请求进入 |
| 设备服务 | 查询或确认设备状态，交换数据，更新地址、计数及请求状态 | 完成本次设备服务 |
| 准备返回 | 关中断，恢复保存的寄存器和原屏蔽字 | 避免恢复过程被打断 |
| 中断返回 | 按体系结构约定恢复返回地址及运行状态 | 继续被打断的程序或外层服务程序 |

</center>

硬件先保存[返回地址与关键状态](CPU.md#保存返回地址和程序状态)，软件再保护将使用的寄存器。支持嵌套时，在关键保护完成后开中断，返回时先关中断，再恢复外层状态，使进入与退出都保持完整。

在单重中断模型中，服务期间保持禁止嵌套，因而不需要上表中服务期间开中断的步骤。多重中断则需要保存每层状态，返回时按嵌套的相反顺序恢复。

我们在处理器一章已经讲过中断处理和子程序调用的区别。完整对照请见[中断处理与子程序调用的区别](CPU.md#中断处理与子程序调用的区别)。

子程序调用的栈帧实例，请见[过程调用](instr.md#过程调用的机器级表示)；中断嵌套的屏蔽字实例，请见[多重中断](#多重中断与中断屏蔽字)。

#### 多重中断与中断屏蔽字

**单重中断** 在服务期间禁止新的可屏蔽中断，**多重中断** 允许符合优先级规则的请求抢占当前服务。屏蔽字的每一位对应一个中断源，本节约定 **1 为屏蔽、0 为允许**。

通常在服务某个源时，屏蔽自身及处理优先级不高于它的源，允许更高处理优先级的源抢占。装入新屏蔽字前先保存原值，返回时恢复，使外层服务或主程序继续使用原来的规则。

!!! note "关中断与源屏蔽的作用不同"

    [关中断](CPU.md#关中断)控制 CPU 是否接受可屏蔽中断，源屏蔽位决定某个请求能否参与判优。请求可以先被记录，在开中断且解除屏蔽后再处理。屏蔽字在主程序和服务程序中均可生效。

!!! example "响应顺序与嵌套处理顺序"

    4 个可屏蔽源的硬件响应优先级为 $A>B>C>D$，处理优先级为 $A>D>C>B$。按位序 **ABCD**，各服务程序的屏蔽字为：

    | 正在服务的源 | 屏蔽字 | 允许抢占的源 |
    | :---: | :---: | --- |
    | A | `1111` | 无 |
    | B | `0100` | A、C、D |
    | C | `0110` | A、D |
    | D | `0111` | A |

    假定主程序开中断且屏蔽字为 `0000`，A、C、D 同时请求；在 C 的服务期间 B 又请求，则执行过程为：

    | 步骤 | 执行变化 | 原因 |
    | :---: | --- | --- |
    | 1 | 主程序 → A，A 完成后返回 | 初始有效请求按硬件顺序先选 A；A 屏蔽全部源 |
    | 2 | 主程序 → C | A 返回后，C、D 中响应顺序先选 C |
    | 3 | C → D，D 完成后返回 C | C 装入 `0110` 并开中断，待处理的 D 可抢占 C |
    | 4 | C 继续，B 的请求等待 | C 的屏蔽字禁止 B 抢占 |
    | 5 | C 返回主程序，再进入 B | 恢复主程序的 `0000` 后，B 可被响应 |

    这个例子中，C 先被响应，D 却能在 C 完成前得到服务，体现了两类优先级的区别。嵌套返回按外层保存的返回地址逐层恢复：D 返回 C，C 完成后再返回主程序。

#### 中断方式的CPU开销

若设备速率为 $R\mathrm{B/s}$，每次中断处理 $g\mathrm{B}$，每次响应与服务总计 $C_{\mathrm{int}}$ 个时钟周期，CPU 主频为 $f$，则：

$$
f_{\mathrm{int}}=\frac{R}{g},
\qquad
t_{\mathrm{int}}=\frac{C_{\mathrm{int}}}{f},
\qquad
U_{\mathrm{int}}=\frac{RC_{\mathrm{int}}}{gf}.
$$

单缓冲、连续到达的基本模型还需使服务能够赶上数据到达速度，即 $t_{\mathrm{int}}\leq g/R$；实际还要给请求等待和其他工作留出时间。$U_{\mathrm{int}}>1$ 表示每秒服务所需周期数超过 CPU 每秒能提供的周期数，该传送方式无法持续处理这一数据流。

例如，$R=40\mathrm{MB/s}$，每次中断传送 4 字节，$f=500\mathrm{MHz}$，响应与服务需要 400 周期，则服务时间为 $0.8\mu\mathrm{s}$，新一份数据每 $0.1\mu\mathrm{s}$ 到达，所需 CPU 比例为 $800\%$。该配置无法采用逐字中断维持这一速率。

中断方式减少了查询等待，但每次仍要付出响应、现场保护、数据搬运和返回开销。高速连续传送时，频繁中断可能成为瓶颈，可进一步考虑[DMA](#dma方式)。

### DMA方式

#### 基本特点

**直接存储器访问**（Direct Memory Access，DMA）由专用控制硬件在外设与主存之间搬运数据。CPU 负责启动前的设置与结束后的处理，块传送期间的数据不经过 CPU 通用寄存器，也不需要 CPU 执行逐字搬运指令。

DMA 自动生成主存地址、维护传送长度并控制读写。它适合高速、成块的数据交换，减少频繁进入服务程序的开销，但需要相应控制器、主存缓冲区及总线控制能力。

DMA 减少了 CPU 的搬运指令，同时占用总线与主存。CPU 与 DMA 同时申请这些资源时，由[访存组织方式](#dma的传送方式)安排先后或分配时隙。

#### DMA控制器的组成

<center class="centered-table" markdown="1">

| 部件 | 作用 |
| --- | --- |
| 主存地址计数器 AR | 保存当前传送位置，初始为数据块起始地址，每次传送后更新 |
| 设备地址或选择信息 DAR | 指定参与传送的外设或接口 |
| 传送长度／字计数器 WC | 记录剩余传送量，基本模型中递减到 0 表示完成 |
| 数据缓冲寄存器 | 暂存主存与设备之间交换的数据 |
| DMA 请求触发器 | 记录设备提出的传送请求 |
| 控制／状态逻辑 | 设置方向，处理总线请求与允许，发出读写命令并修改参数 |
| 中断机构 | 在整块完成或出现需要处理的事件时通知 CPU |

</center>

控制器接收设备的 DMA 请求后，申请总线；获得允许后取得主设备资格，输出地址和控制信号完成传送，再按方式释放通路。[总线主设备](bus.md#总线事务)与[总线仲裁](bus.md#总线仲裁)的概念同样适用。

地址和长度按各自单位更新：按字节编址、每次传送 4 字节时，地址增加 4；计数器若按字计数就减 1，按字节计数就减 4。

#### DMA的传送方式

DMA 与 CPU 都可能访问主存，常见的共享方式如下：

<center class="centered-table" markdown="1">

| 方式 | 总线与主存怎样分配 | 特点 |
| --- | --- | --- |
| 停止 CPU 访存 | DMA 取得控制权后连续传送整块，再交还 CPU | 控制简单、适合高速成块传送，但 CPU 的访存等待时间长 |
| 周期挪用 | 每传送一个字占用一个相应的主存周期，然后释放 | 可在 CPU 访问间隙穿插，也会推迟冲突的 CPU 访问；有申请与释放开销 |
| DMA 与 CPU 交替访存 | 预先把访问时间划成双方各自的时隙 | 无须每次动态申请，但需要主存速度和控制时序支持 |

</center>

采用周期挪用时，有三种基本情况：CPU 当前不访存，DMA 可在允许的空闲时段访问；CPU 正在访存，先完成这次访问再转交；双方同时请求，按仲裁规则选择，基本教学模型通常优先满足 DMA，避免外设缓冲来不及处理。

周期挪用占用的是主存访问机会，CPU 保持原来的程序上下文。在依赖主存供指、供数的简单结构中，暂停访存会使 CPU 等待；若指令与数据已在其他可用资源中，则相应执行可以继续。

交替访存要求预定时隙足够完成访问。例如，一个分配周期为 $1.2\mu\mathrm{s}$，分成两个 $0.6\mu\mathrm{s}$ 时隙，就需要相应主存访问和控制操作能在各自时隙内完成。

#### DMA的传送过程

<center class="centered-table" markdown="1">

| 阶段 | 执行者 | 主要工作 |
| --- | --- | --- |
| 预处理 | CPU 执行程序 | 设置主存起始地址、设备、方向与传送量，启动 DMA 和设备 |
| 数据传送 | DMA 控制器 | 响应设备请求，取得所需通路，搬运数据，修改地址及计数，直到整块完成 |
| 后处理 | CPU 通常通过完成中断执行程序 | 检查完成或错误状态，作必要处理并安排后续工作 |

</center>

DMA 一次设置和完成通知管理一个 **数据块**，块内逐字或按突发方式传送。整块连续占用总线、逐次周期挪用或固定交替时隙，分别对应前面的[传送方式](#dma的传送方式)。

完成通知使用的仍是中断机制，其响应和状态保护的进一步内容可见[异常和中断的响应过程](CPU.md#异常和中断的响应过程)。因此，DMA 数据搬运阶段不需要逐次保存 CPU 现场，而结束后的中断服务仍需要保护现场。

#### DMA开销的计算

假定速率为 $R\mathrm{B/s}$，每个 DMA 块为 $L\mathrm{B}$，每块预处理与后处理共需 $C_{\mathrm{block}}$ 个 CPU 时钟周期，则 CPU 执行这些控制工作的时间比例为：

$$
f_{\mathrm{block}}=\frac{R}{L},
\qquad U_{\mathrm{DMA}}=\frac{RC_{\mathrm{block}}}{Lf}.
$$

例如，$R=40\mathrm{MB/s}$，$L=1000\mathrm{B}$，每块前后处理需要 500 周期，CPU 主频为 $500\mathrm{MHz}$：

$$
f_{\mathrm{block}}=40000\mathrm{/s},
\qquad U_{\mathrm{DMA}}=\frac{40000\times500}{500\times10^6}=4\%.
$$

$C_{\mathrm{block}}$ 表示每块控制工作占用的时钟周期数，$f$ 表示 CPU 每秒可提供的周期数。若控制工作由指令条数描述，其时钟周期开销等于指令数乘以平均 CPI。

这个比例统计预处理与后处理所执行的 CPU 指令。总线仲裁和主存争用造成的等待，依据相应时序另行计入受影响的时间。

#### DMA与程序中断方式的区别

<center class="centered-table" markdown="1">

| 对比项 | 程序中断 I/O | DMA |
| --- | --- | --- |
| 数据搬运者 | CPU 执行服务程序 | DMA 硬件 |
| 数据通路 | 接口与主存之间通过 CPU 搬运 | 接口与主存之间直接传送 |
| 请求的主要目的 | 让 CPU 执行服务程序 | 让控制器取得传送通路 |
| 请求响应时机 | 可屏蔽外中断在允许的指令边界响应 | 可在当前不可中断的总线访问结束后交接，无须等整条指令结束 |
| 现场保护 | 每次进入服务都要按约定保护现场 | 数据搬运本身无须切换程序；完成中断仍需保护现场 |
| CPU 参与程度 | 每次服务都要执行搬运及控制指令 | 主要参与块开始前和完成后的工作 |
| 适用任务 | 需要程序处理的设备服务与一般事件 | 高速、大批量数据传送 |

</center>

**DMA 请求** 向总线控制逻辑申请数据传送机会，**DMA 完成中断** 则通知 CPU 执行软件后处理；二者分别按总线交接与中断响应的规则处理。
