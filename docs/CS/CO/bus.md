# 总线

CPU、主存和外部设备需要交换信息。若为每一对部件都设置专用连线，部件增加时，连接与扩展就会越来越复杂。**总线**（Bus）提供一组公共传输线路，让多个部件按约定使用同一条通信通路。

## 总线概述

总线的两个核心特点是 **分时与共享**：多个部件可以连接到同一组线路上，但在同一时刻，不能让多个发送方驱动同一组共享数据线。接收方则可按选择信号接收信息，广播传输中也可有多个接收方。

总线本身不保存信息，暂存数据需要寄存器或缓冲器。CPU 内部利用总线传送操作数的例子，见[单总线数据通路](CPU.md#单总线结构的数据通路)。

### 总线的分类

按连接位置和使用范围，可以区分以下类型：

<center markdown="1">

| 类型 | 连接的部件 | 主要用途 |
| --- | --- | --- |
| 内部总线／片内总线 | 芯片内部的寄存器、ALU 等 | 完成芯片内部的信息传送 |
| 系统总线 | CPU、主存、I/O 接口等系统部件 | 连接计算机的主要功能部件 |
| I/O 总线 | 主机与显卡、网卡等 I/O 控制器 | 为外围控制器提供扩展和连接通路 |
| 通信总线 | 主机与外部设备，或不同系统之间 | 适应设备连接距离及相应电气、传输规范 |

</center>

这些名称描述不同的观察角度，具体平台的划分可能有所不同。这里的“内部总线”指片内连接，不能把机箱内部的所有设备连接都归入这一类。

在基本系统总线模型中，按传送信息的用途，又可划分为三组：

<center markdown="1">

| 类别 | 传送的内容 | 方向与位数的含义 |
| --- | --- | --- |
| 数据总线 | 指令、操作数、状态字、中断类型号等 | 通常双向；数据线数量决定一次并行传送的数据位数 |
| 地址总线 | 主存单元或 I/O 端口的地址 | 在一次事务中由主设备发向目标设备；地址位数决定可区分的地址数量 |
| 控制总线 | 读写、时钟、复位、请求、允许、确认等信号 | 各信号有各自的方向，不能把整组控制线一律看成单向或双向 |

</center>

这里的“数据”是在线路上传送的编码信息，并不限于程序的操作数。例如，I/O 接口的控制命令字通过数据线写入控制寄存器，而“本次是写操作”由控制线表明，具体见[I/O 接口的基本结构](co_IO.md#io接口的基本结构)。

CPU 是常见的总线主设备，但[DMA 控制器](co_IO.md#dma方式)也能取得总线控制权并发出地址。因此，“地址总线单向”应结合一次事务的主从关系理解。

### 常见的总线标准（*）

**总线标准** 规定互连的电气、机械和传输协议等要求，便于不同部件采用相容的接口。标题后的“（*）”表示扩展阅读内容。

下表按本节涉及的典型实现整理传统标准与接口。串行、并行描述数据怎样传送；系统、局部或设备接口描述使用位置，属于不同分类维度。

<center markdown="1">

| 名称 | 英文名称或含义 | 典型特点 |
| --- | --- | --- |
| ISA | Industry Standard Architecture | 早期并行系统总线，传输能力较低 |
| EISA | Extended ISA | 扩展 ISA，支持多主控器和突发传送，并兼容 ISA |
| VESA 局部总线 | Video Electronics Standards Association | 面向高速图形等需求的 32 位并行局部总线 |
| PCI | Peripheral Component Interconnect | 与处理器时钟相对独立的 32 位或 64 位并行外围总线，支持即插即用 |
| AGP | Accelerated Graphics Port | 为图形卡设置的专用并行接口 |
| PCI Express／PCIe | PCI Express | 高速串行点对点互连，可组合多条通道，支持全双工 |
| RS-232C | 串行通信接口标准 | 用于数据终端与通信设备等的串行连接 |
| USB | Universal Serial Bus | 外设串行连接，支持即插即用、热插拔及多设备连接 |
| PCMCIA | Personal Computer Memory Card International Association | 传统笔记本并行扩展卡接口，支持即插即用 |
| IDE／ATA | Integrated Drive Electronics／ATA | 硬盘、光驱等的传统并行设备接口 |
| 传统 SCSI | Small Computer System Interface | 常用于存储设备的并行接口 |
| SATA | Serial ATA | ATA 系列的串行设备接口 |

</center>

局部总线的设计思路，是为高速外围部件提供比传统低速扩展总线更直接的连接。PCIe 的“串行”也不表示整条链路只有一条通道；多条串行通道可共同提供更大的传输能力。

### 总线的性能指标

#### 时钟、传输周期与宽度

<center markdown="1">

| 指标 | 含义 |
| --- | --- |
| 总线时钟周期 $T_b$ | 总线基础时钟的一个周期 |
| 总线时钟频率 $f_b$ | $1/T_b$，不必等于 CPU 主频 |
| 总线传输周期／总线周期 | 完成一次总线事务所需的时间，可包含多个总线时钟周期 |
| 总线工作频率／传输频率 | 每秒有效数据传输的次数，可高于基础时钟频率 |
| 总线宽度 $w$ | 并行数据线的位数，即一次数据传送的位数 |

</center>

若一个事务需要 $m$ 个基础时钟周期，则其时间为 $mT_b$。若每个时钟周期可传送 $q$ 次数据，则传输频率为 $qf_b$。**事务需要几个周期，与每周期能传送几次数据，是两个不同的问题**。

#### 总线带宽

在并行总线的基本模型中，理论峰值带宽为：

$$
B_{\mathrm{peak}}=w\times qf_b\quad(\mathrm{bit/s}),
\qquad
B_{\mathrm{peak}}=\frac{w}{8}\times qf_b\quad(\mathrm{B/s}).
$$

例如，数据总线宽 16 位，时钟为 $11\mathrm{MHz}$，每周期传送两次，则：

$$
B_{\mathrm{peak}}=\frac{16}{8}\times2\times11\times10^6
=44\mathrm{MB/s}.
$$

这里带宽单位中的 $\mathrm{M}$ 按 $10^6$ 计算。求字节数前要把位宽除以 8，不能混淆 MB/s 与 Mb/s。

实际事务还可能包含地址、命令、响应等待和仲裁等开销，因此平均有效传输率应按：

$$
B_{\mathrm{effective}}=
\frac{\text{实际传送的有效数据量}}{\text{完整传输耗时}}.
$$

峰值带宽由物理传输参数决定，平均速率还要结合[总线事务的时序](#总线事务)。突发传送减少事务开销，可以提高平均速率，但不改变相同物理参数下的峰值带宽。

#### 总线复用与寻址能力

**总线复用** 让同一组物理线路在不同时间传送不同信息，例如先送地址、再送数据。这可以减少引脚与连线，但接收方需要按阶段识别，并在必要时锁存先前信息。

地址与数据复用，不意味着它们在逻辑上没有区别，也不意味着可以同时使用复用线路传送两种不同信息。

若完整地址为 $a$ 位，则可区分 $2^a$ 个地址。最大寻址容量还要乘以[编址单位](storage.md#编址单位与寻址范围)：

$$
\text{最大寻址容量}=2^a\times\text{每地址对应的容量}.
$$

地址位数决定地址数量，数据宽度决定一次传送多少位，两者不能互相替代。采用分时复用时，还应区分完整地址位数与物理引脚数量。

### 总线的结构

#### 早期共享总线结构

<center markdown="1">

| 结构 | 基本连接思路 | 性能影响 |
| --- | --- | --- |
| 单总线 | CPU、主存和各类 I/O 接口共享系统总线 | 结构简单，通信竞争集中在同一通路 |
| 双总线 | 增设 CPU—主存的专用存储通路 | 减少普通 I/O 对存储通路的直接占用；某些结构中 I/O 与主存仍需 CPU 中转 |
| 三总线 | 在上述思路上增加 DMA 通路 | 高速 I/O 可由 DMA 控制器直接与主存交换数据 |

</center>

总线条数的名称要结合具体结构图理解。三总线结构中的 DMA 通路，解决的是设备与主存的数据交换问题；CPU 内部的三总线数据通路则可能分别传送两个源操作数和一个结果，见[数据通路的分类](CPU.md#数据通路的组织与分类)。

#### 传统分层总线：南北桥结构

南北桥把设备按带宽需求分层连接：

- **北桥**（MCH）连接 CPU、主存和高速图形通路，负责高带宽传输。
- **南桥**（ICH）连接 USB、磁盘等外围控制器，管理较低速的 I/O 通路。
- **前端总线**（FSB）连接 CPU 与北桥；南、北桥之间通过桥间通路连接。

典型访问路径可以写成：

$$
\text{CPU}\to\text{FSB}\to\text{北桥}\to\text{主存},
$$

$$
\text{外围设备}\to\text{设备控制器／南桥}\to\text{北桥}
\to\text{CPU 或主存通路}.
$$

高速部件与低速部件由不同通路连接，缓解了单总线上的直接竞争。不过，CPU 与其他部件之间的通信仍依赖共享 FSB，前端总线带宽可能成为瓶颈。外设到主存的 DMA 数据不必由 CPU 执行指令逐字中转。

#### 集成化与点对点互连

进一步的设计把内存控制器等功能集成进 CPU，并为不同通信需求提供相应路径：

<center markdown="1">

| 变化 | 带来的作用 |
| --- | --- |
| 内存控制器集成到 CPU | 缩短 CPU 到主存的路径，减少桥接中转 |
| 多个存储通道 | 各通道可并行传送，提高可用总带宽 |
| 处理器间点对点链路 | 为多个处理器提供专用互连，减少单一共享总线的限制 |
| 高速外设通过 PCIe 接入 | 为图形、存储等控制器提供高速路径 |
| 其他外围接口由 PCH 等集线器管理 | 保留分层连接，协调多种外围设备 |

</center>

相同通道条件下，$c$ 个独立存储通道的理论总带宽可按单通道的 $c$ 倍估算，实际效果仍取决于是否同时使用各通道。多处理器的本地、远程内存访问问题见[UMA 与 NUMA](CPU.md#uma与numa)。

## 总线事务和定时

### 总线事务

**总线事务** 是主设备和目标从设备之间的一次完整信息交换。主设备发起并控制事务，例如 CPU 或 DMA 控制器；从设备响应请求，例如主存或 I/O 接口。读写是数据传送方向，主从是控制关系，不能因读操作中从设备输出数据就颠倒二者。

常见事务包括主存读写、I/O 读写和中断响应。取得共享总线使用权的机制见[总线仲裁](#总线仲裁)。一个基本读事务可分为：

<center markdown="1">

| 阶段 | 主要动作 |
| --- | --- |
| 地址与命令传送 | 主设备给出目标地址和读写等操作类型 |
| 从设备响应／数据准备 | 从设备选中相应位置并准备本次交换所需的数据 |
| 数据传送 | 双方按协议完成数据交换 |

</center>

实际分析时，应按题目给出的阶段时间计算。一次“读数据”不能只计算最后的数据线传送时间，而忽略地址和响应开销。

#### 非突发与突发传送

**非突发传送** 每次传送一个数据单元，每个单元都重新经历地址、准备和数据传送。**突发传送** 给出一个数据块的首地址后，连续传送多个数据单元，由硬件形成后续地址，摊薄地址和命令开销。

假设每个数据单元占 $d$ 字节，地址阶段为 $t_a$，数据准备为 $t_r$，每次数据传送为 $t_d$。在突发期间可连续供数、只计一次初始准备的模型中，传送 $n$ 个单元需要：

$$
T_{\mathrm{nonburst}}=n(t_a+t_r+t_d),
\qquad
T_{\mathrm{burst}}=t_a+t_r+nt_d.
$$

两者有效数据量均为 $nd$，代入[平均有效传输率](#总线带宽)即可比较。如果设备还需要后续等待、分批突发或额外确认，应把这些时间加入对应事务。

后续地址的增量取决于编址单位和每次传送量。例如，按字节编址并连续传送 4 字节字时，相邻字的地址相差 4，不能一律写成“地址加 1”。

#### 串行与并行传送

<center markdown="1">

| 方式 | 数据组织 | 连接特点 |
| --- | --- | --- |
| 串行 | 各位按顺序传送 | 单通道引脚少，适合较长距离，也可通过高速或多通道提高带宽 |
| 并行 | 多位经多条数据线同时传送 | 适合较短距离，但多线间的时序偏移和串扰会限制高速传输 |

</center>

“并行”不保证比“串行”更快，还要比较传输频率、通道数量和协议开销。多个独立串行通道也可以同时工作。

串行通信按位同步方式又可区分同步与异步。同步串行传送需要收发双方维持位同步；异步字符传送则在每个字符中加入起止标记，让接收方确定采样起点。

典型异步字符的组成是：

$$
\boxed{\text{起始位}\;\mid\;\text{数据位}\;\mid\;
\text{可选校验位}\;\mid\;\text{停止位}}.
$$

通常空闲状态为逻辑 1，起始位为逻辑 0，停止位为逻辑 1，数据从低位开始传送。以 1 个起始位、8 个数据位、无校验、1 个停止位为例，每字符共传送 10 位，数据位只占 $8/10=80\%$。若线路位速率为 $R_{\mathrm{bit}}$，则有效字节速率为 $R_{\mathrm{bit}}/10$。

### 总线定时

**总线定时** 是主从设备协调地址、命令与数据传送时刻的规则。总线的同步、异步定时讨论事务控制，上一节的同步、异步串行通信讨论串行字符或数据位的组织，分析时要先确认所讨论的层次。

#### 同步定时

双方按照统一总线时钟，在预先规定的时刻发送和接收信号。基本固定时序模型中，每次事务占用规定数量的节拍，从设备须在规定期限内完成准备。

这种方式控制简单、传送较快，适合连接距离短、部件速度相近的系统。但若没有额外就绪反馈，就不能灵活适应从设备响应时间变化，需要按规定的最坏时间安排操作。

#### 异步定时与互锁

异步定时不依赖统一的总线时钟，而是通过 **请求与回答** 协调操作。从设备准备就绪后再回答，使事务时间能够适应不同设备的响应速度。

按信号撤销是否依赖对方确认，可以分为三种：

<center markdown="1">

| 方式 | 主设备何时撤销请求 | 从设备何时撤销回答 |
| --- | --- | --- |
| 不互锁 | 发出请求后按预定延时撤销 | 发出回答后按预定延时撤销 |
| 半互锁 | 收到回答后才撤销请求 | 发出回答后按预定延时撤销 |
| 全互锁 | 收到回答后才撤销请求 | 确认请求已撤销后才撤销回答 |

</center>

全互锁的事件顺序为“发请求 → 发回答 → 撤请求 → 撤回答”。双方对信号撤销都作确认，可靠性较高，但增加了信号交互与传播开销。异步定时适合设备速度差异较大的连接，控制通常比固定同步时序复杂。

#### 半同步定时

半同步定时以统一时钟为基础，同时增加等待或就绪反馈。主设备在规定时钟边沿检查从设备状态：若尚未准备好，就插入等待周期；准备完成后继续传送。

它既保留时钟约束，也能延长事务以适应慢速设备。等待信号的高低电平含义应由协议规定，不能仅凭 `Wait`、`Ready` 等名称推断有效电平。

#### 分离式定时

前面几种基本模型在请求发出到传输完成之间通常由一个事务占用总线。若从设备准备较慢，总线会在等待期间闲置。

**分离式定时** 把事务分成请求与应答两个阶段：

1. 请求方取得总线，发送地址和命令，然后释放总线。
2. 从设备在准备数据期间，其他事务可以使用总线。
3. 从设备准备好后，重新取得总线，以应答阶段主设备的身份返回结果。

它提高了总线利用率，但需要管理未完成事务及其对应的应答，并增加仲裁与协议控制。多个事务可以同时处于“已请求、尚未完成”的状态，每一时刻的共享传送通路仍需按规则分配。

## 本章小结

### 引入总线的收益与代价

公共连接减少了专用连线，使接口更规整，支持模块化设计、扩展、配置和维护。采用标准化接口还便于连接不同功能部件，降低重复设计的成本。

共享通路也会形成带宽竞争。提高传输频率、扩大有效宽度、使用[突发传送](#非突发与突发传送)、分层或增加独立通路，分别针对不同瓶颈；多主设备的控制权竞争还需要仲裁。

### 总线仲裁

**总线仲裁** 在多个主设备同时申请共享通路时，决定由谁取得控制权。获得控制权的主设备才能发起相应传送；仲裁部件负责选择，不能与“当前发起事务的主设备”混为一谈。

仲裁可以采用集中式判定，也可由各申请者按协议分布式决定。常见思路包括链式传递允许信号、集中并行判优和分布式自选择。设计时既要考虑优先级，也要考虑公平性，避免某个申请者长期无法取得通路。

仲裁决定 **谁先使用总线**，[总线定时](#总线定时)决定 **取得通路后怎样协调传送**。它与[I/O 中断判优](co_IO.md#中断请求与响应判优)的对象不同：后者选择 CPU 接下来响应哪个中断请求。

## 常见问题和易混淆知识点

### 同一时刻能有多对主从设备通信吗？

对同一组共享数据线，通信必须遵守[分时使用规则](#总线概述)，不能让多对设备同时传送不同数据。广播可以由一个发送方把同一信息交给多个接收方。

多条独立总线或点对点链路可以各自进行传输；[分离式事务](#分离式定时)也可使多个请求同时等待应答。它们都要与“同一共享数据通路在同一时刻由多个发送方驱动”区分。
