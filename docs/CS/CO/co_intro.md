# 计算机系统概述

从写下一段程序，到屏幕上出现运行结果，中间发生了什么？程序需要被翻译成机器指令，装入存储器，再由 CPU 取出并执行；输入、输出和存储设备则不断与主机交换信息。计算机组成原理研究的，就是这些操作怎样由硬件协同完成。

## 计算机的发展历程\*

### 硬件的发展

按主要逻辑元件的变化，电子数字计算机的发展通常分为四代。

<center markdown="1">

| 阶段 | 主要逻辑元件 | 存储与软件的发展 |
| --- | --- | --- |
| 第一代，<br>1946～1957 年 | 电子管 | 使用延迟线、磁鼓等存储器，以机器语言编程；体积大、成本高，速度约为每秒几千至几万次运算 |
| 第二代，<br>1958～1964 年 | 晶体管 | 采用磁芯存储器，出现高级语言及编译程序、操作系统的雏形，速度提高到每秒几万至几十万次运算 |
| 第三代，<br>1965～1971 年 | 中小规模集成电路 | 半导体存储器逐步取代磁芯存储器，高级语言普及，分时操作系统发展 |
| 第四代，<br>1972 年以来 | 大规模、超大规模集成电路 | 微处理器、半导体存储器不断发展，流水线、Cache、虚拟存储器和并行处理得到广泛应用 |

</center>

集成电路让更多晶体管进入同一芯片，既提高集成度，也为增加寄存器、运算部件和缓存提供了条件。**摩尔定律** 概括了这种集成度的增长趋势，通常表述为成本增长很少时，芯片上的晶体管数量约每两年翻一番；摩尔在 1975 年把早期的每年翻倍预测修订为这一周期。晶体管数量带来的性能收益，取决于这些资源怎样被组织和使用。

!!! info "拓展信息"
    [Intel 的摩尔定律说明](https://www.intel.com/content/www/us/en/newsroom/resources/moores-law.htm)

半导体存储器的单芯片容量从 KiB 级逐步发展到更大规模，存储系统同时通过多芯片组合扩大容量。微处理器也从 Intel 4004 等早期器件，发展到 8 位、16 位、32 位和 64 位处理器。这里的位数指 **机器字长**，即基本整数数据通路、通用寄存器的宽度；地址宽度另由体系结构规定。

### 软件的发展

编程语言从机器语言、汇编语言发展到高级语言，使程序员逐渐能够围绕问题本身组织程序。例如，FORTRAN 面向科学计算，Pascal 支持结构化程序设计，C++ 支持面向对象程序设计，Java 提供跨平台的运行体系。

与此同时，操作系统、编译器、数据库管理系统等系统软件逐渐完善。硬件提供更多计算与存储能力，软件负责把这些资源组织成可使用的功能，两者共同推动计算机系统的发展。

## 计算机系统的组成

一个完整的 **计算机系统** 由硬件和软件组成。硬件是 CPU、存储器、外部设备等物理装置；软件包括程序，以及相关的数据和文档。

### 冯·诺依曼结构

**存储程序** 的思想，是把程序指令和初始数据预先存入存储器。启动后，计算机按指令地址自动取指、译码并执行，依照程序规定的控制流连续工作。

**冯·诺依曼机** 的基本特点可以归纳为：

1.  采用存储程序的工作方式。
2.  硬件由 **运算器、控制器、存储器、输入设备和输出设备** 五大功能部件组成。
3.  指令和数据都用二进制编码，并以同等地位存放在存储器中。
4.  指令主要由操作码和地址码组成：操作码规定做什么，地址码提供操作数或目标位置等信息。

存储器保存的是位串。取指时，CPU 把读出的内容送入指令译码路径；取操作数时，则把内容送往寄存器和运算部件。**同一段二进制的用途，由当前执行阶段和控制信号所选择的流向决定**。

### 硬件的功能部件

<center markdown="1">

| 部件 | 主要工作 | 后续内容 |
| --- | --- | --- |
| CPU | 取指、译码、执行运算，控制各部件按时序工作 | [中央处理器](CPU.md) |
| 主存储器 | 保存正在使用的程序和数据，按地址读写 | [存储系统](storage.md) |
| 外部设备 | 输入信息、输出结果，或长期保存数据 | [输入/输出系统](co_IO.md) |
| I/O 控制器／接口 | 控制设备，缓冲数据，向主机提供命令、数据和状态端口 | [I/O 接口](co_IO.md#io接口) |
| 总线及互连 | 在 CPU、主存和 I/O 接口之间传送地址、数据和控制信息 | [总线](bus.md) |

</center>

CPU 的传统功能划分是 **运算器与控制器**。分析具体实现时，通常把寄存器、ALU 和传送路径组织为 **数据通路**，再由控制单元产生控制信号，选择数据来源、运算类型及结果写入位置。

存储器按所处层次可分为 Cache、主存和辅存。Cache 保存近期活跃的指令、数据块，主存是程序执行的工作存储空间，磁盘、SSD、磁带和光盘等辅存负责保存更多信息。辅存中的程序和数据通常先调入主存，再供 CPU 使用。

外设负责实际的物理操作，控制器负责与主机通信和组织这些操作。例如，键盘产生输入信息，键盘接口报告状态并提供数据；磁盘驱动机构完成定位和读写，磁盘控制器接收主机命令并安排传输。

### 系统软件与应用软件

- **系统软件** 管理资源并提供基础运行环境，如操作系统、数据库管理系统、语言处理程序、网络与分布式系统软件、标准库和服务性程序。
- **应用软件** 用于解决具体任务，如科学计算、工程设计、数据统计、办公和信息处理。

同一种逻辑功能可以由硬件实现，也可以由软件实现，这称为 **软硬件逻辑功能等价性**。例如，浮点运算可以由专用硬件执行，也可以由软件例程按相同数值规则模拟。实现方式会影响速度、成本和修改难度：使用频繁、适合并行的功能往往值得用硬件加速，变化较多的功能则更适合由软件组织。

## 计算机系统的层次结构

### 从应用到电路

我们可以沿着一个计算任务，逐层观察计算机系统：

<center markdown>
**应用问题 → 算法与程序 → 操作系统及运行环境 → ISA → 微体系结构 → 功能部件与 RTL → 电路与器件**
</center>

每层使用下层提供的能力，并向上层提供更容易使用的接口。操作系统通过资源管理和服务接口扩展了裸机的功能；高级语言进一步隐藏寄存器分配、机器指令编码等细节。

**指令集体系结构**（Instruction Set Architecture，ISA）是软件与硬件之间的关键接口，规定指令格式、操作类型、数据类型、寻址方式、程序可见寄存器和控制状态等。

**微体系结构** 决定怎样实现 ISA，例如采用什么数据通路、几级流水线、什么 Cache 组织和分支预测方式。提供乘法指令属于体系结构的规定；用迭代乘法器还是阵列乘法器实现它，属于计算机组成的问题。相同 ISA 的不同实现可以具有不同的速度、成本与功耗。

### 不同用户看到的计算机

<center markdown="1">

| 角色 | 主要关注的层次与任务 |
| --- | --- |
| 最终用户 | 通过应用程序完成办公、浏览、计算等任务 |
| 系统管理员 | 配置系统，管理账户，安装软硬件，备份与维护数据 |
| 应用程序员 | 使用高级语言、库与系统接口开发应用程序 |
| 系统程序员 | 实现操作系统、编译器、数据库等，使用 ISA 和系统级资源 |

</center>

这些角色可以由同一个人在不同场景下承担。进一步向硬件内部观察，架构师关注 ISA、微体系结构与功能部件的组织，电子工程师关注电路和器件实现。

!!! tip "透明性是相对于观察者而言的"
    在计算机领域，某个细节对一类用户 **透明**，表示该用户使用系统时无须感知或管理它。例如，应用程序员通常无须管理 Cache 行的替换；机器语言程序员需要知道 ISA 中寄存器和指令的规定，而 IR、MAR、MDR 等内部暂存部件由硬件管理。

## 程序怎样运行

### 机器语言、汇编语言与高级语言

- **机器语言** 直接用二进制指令编码描述操作，由 CPU 识别和执行。
- **汇编语言** 用助记符、寄存器名和符号地址表示机器级操作，需要汇编器生成机器代码。
- **高级语言** 用变量、表达式和控制结构描述算法，通常经编译或解释执行。

**翻译程序** 完成语言表示之间的转换。其中，汇编器把汇编程序转换为机器代码；编译器把高级语言程序转换为汇编语言、机器代码等目标表示。解释器在运行过程中分析并执行程序，在基础模型中表现为逐句处理、边解释边执行。

这里还要区分“汇编语言源程序”和“汇编程序”：前者是待翻译的代码，后者在指工具时就是汇编器。编译与解释描述的是语言的实现方式，同一种语言也可以采用不同实现。

### 从 C 源文件到可执行文件

以 `hello.c` 为例，典型的构建过程分为四个阶段：

$$
\texttt{hello.c}\xrightarrow{\text{预处理}}\texttt{hello.i}
\xrightarrow{\text{编译}}\texttt{hello.s}
\xrightarrow{\text{汇编}}\texttt{hello.o}
\xrightarrow{\text{链接}}\texttt{hello}.
$$

1.  **预处理**：处理头文件包含、宏展开、条件编译等，得到修改后的 C 源程序，仍是文本。
2.  **编译**：把高级语言程序翻译为汇编程序，进行相应分析与优化，输出仍是文本。
3.  **汇编**：把汇编程序转换为可重定位目标文件，其中包含机器代码、数据、符号及重定位信息，是二进制文件。
4.  **链接**：合并目标文件和所需库代码，解析外部符号引用，完成必要的重定位，形成可执行目标文件。

例如，对 `printf` 的调用需要与提供该功能的库连接起来。可执行文件保存在辅存中，运行时由操作系统装入所需内容、建立运行环境，并把控制权交给程序入口。

### CPU 的取指—执行循环

程序开始执行时，先把入口地址装入 **程序计数器 PC**。此后 CPU 重复：

$$
\text{按 PC 取指}\to\text{译码}\to\text{取操作数并执行}
\to\text{保存结果、确定后继地址}\to\text{再次取指}.
$$

顺序执行时，后继地址等于本条指令地址加上指令长度；转移、调用、返回等指令则按各自规则改变 PC。例如，按字节编址的 32 位定长指令占 4 字节，顺序地址每次增加 4。

这样一来，这条执行链就串起了软件和硬件：[指令系统](instr.md)规定每条指令的语义，[CPU 的数据通路与控制器](CPU.md#数据通路的功能和基本结构)把语义实现为寄存器传送、运算和访存操作。

## 计算机的性能指标

### 吞吐量与响应时间

**吞吐量** 是单位时间完成的任务或请求数量，描述系统持续处理任务的能力；**响应时间** 是从提出请求到取得结果经历的总时间，描述单个任务的完成速度。

响应时间包括程序占用 CPU 的时间，以及 I/O、排队等等待时间。吞吐量则还受输入、处理、存储与输出各环节的共同约束。例如，增加处理器可能让系统同时处理更多请求，而单次磁盘访问的等待仍取决于存储设备。

### 主频、CPI 与 CPU 执行时间

**时钟周期** $T_{\mathrm{clk}}$ 是 CPU 主时钟的一个周期；**主频** $f$ 是每秒的周期数，二者互为倒数：

$$
T_{\mathrm{clk}}=\frac{1}{f}.
$$

例如，$2\mathrm{GHz}$ 对应 $0.5\mathrm{ns}$。时钟周期要容纳相应数据通路的传播与状态更新，具体约束见[数据通路与时钟周期](CPU.md#数据通路与时钟周期)。

**CPI**（Cycles Per Instruction）是平均每条指令所需的时钟周期数。设第 $i$ 类指令执行 $I_i$ 次、每次需要 $C_i$ 个周期，总动态指令数为 $I=\sum_i I_i$，则：

$$
N_{\mathrm{clk}}=\sum_i I_iC_i,\qquad
\mathrm{CPI}=\frac{\sum_i I_iC_i}{\sum_i I_i}
=\sum_i\frac{I_i}{I}C_i.
$$

CPI 按 **实际执行次数** 加权。例如，某程序含有两类指令，它们的 CPI 分别为 1、4，执行比例分别为 $75\%$、$25\%$，平均 CPI 为 $1\times0.75+4\times0.25=1.75$，那么程序的 CPU 执行时间为：

$$
T_{\mathrm{CPU}}=N_{\mathrm{clk}}T_{\mathrm{clk}}
=I\times\mathrm{CPI}\times T_{\mathrm{clk}}
=\frac{I\times\mathrm{CPI}}{f}.
$$

**指令数、平均 CPI 和主频共同决定执行时间**。编译优化、指令集设计、流水线和存储系统都可能改变其中一个或多个量。

!!! example "CPI 变化对主频收益的影响"
    两台机器执行同一指令序列：M1 的主频为 $2\mathrm{GHz}$，执行时间为 $10\mathrm{s}$；M2 的平均 CPI 是 M1 的 1.5 倍，执行时间为 $6\mathrm{s}$。

    M1 使用的周期数为 $10\times2\times10^9=2\times10^{10}$。由于动态指令数相同，M2 的总周期数随 CPI 增为 $3\times10^{10}$，其执行时间对应的主频为：

    $$
    f_2=\frac{3\times10^{10}}{6}=5\mathrm{GHz}.
    $$

    在这个例子里，主频提高到原来的 2.5 倍，执行速度相对地却只提高到原来的 $10/6\approx1.67$ 倍，较高的 CPI 抵消了部分主频收益。

### IPS、MIPS 与浮点运算速度

**IPS**（Instructions Per Second）表示每秒完成的指令数，进一步有 **MIPS** 表示每秒完成多少百万条指令：

$$
\mathrm{IPS}=\frac{I}{T_{\mathrm{CPU}}}=\frac{f}{\mathrm{CPI}},\qquad
\mathrm{MIPS}=\frac{f}{\mathrm{CPI}\times10^6}.
$$

不同 ISA 的一条指令可能完成不同工作，MIPS 也随程序的指令构成及编译结果变化。它描述特定指令序列的执行速率，任务的完成速度则由总执行时间体现。

**FLOPS**（Floating-point Operations Per Second）表示每秒完成的浮点运算次数：

$$
\mathrm{FLOPS}=\frac{\text{浮点运算次数}}{\text{执行时间(s)}}.
$$

<center markdown="1">

| 指标 | 每秒浮点运算次数 |
| --- | --- |
| MFLOPS | $10^6$ |
| GFLOPS | $10^9$ |
| TFLOPS | $10^{12}$ |
| PFLOPS | $10^{15}$ |
| EFLOPS | $10^{18}$ |
| ZFLOPS | $10^{21}$ |

</center>

!!! note "计量单位前缀：十的幂与二的幂"

    词头表示一个数量级。十进词头来自国际单位制（SI），常用符号和含义如下：

    <center markdown="1">

    | 符号 | 名称 | 含义 | 数值 |
    | --- | --- | --- | --- |
    | k/K | kilo | 千 | $10^3$ |
    | M | mega | 兆 | $10^6$ |
    | G | giga | 吉 | $10^9$ |
    | T | tera | 太 | $10^{12}$ |
    | P | peta | 拍 | $10^{15}$ |
    | E | exa | 艾 | $10^{18}$ |
    | Z | zetta | 泽 | $10^{21}$ |
    | Y | yotta | 尧 | $10^{24}$ |
    
    </center>

    二进制词头在十进词头符号后加 i，专门表示二的幂：$\mathrm{Ki}$（kibi）$=2^{10}$、$\mathrm{Mi}$（mebi）$=2^{20}$、$\mathrm{Gi}$（gibi）$=2^{30}$、$\mathrm{Ti}$（tebi）$=2^{40}$，继续还有 $\mathrm{Pi}$（pebi）$=2^{50}$、$\mathrm{Ei}$（exbi）$=2^{60}$、$\mathrm{Zi}$（zebi）$=2^{70}$、$\mathrm{Yi}$（yobi）$=2^{80}$。它们的名称由相应的十进词头与 binary 缩合而成，例如 kibi 来自 kilo + binary。

    本组笔记中，凡按二的幂计量的存储容量，写作 $\mathrm{KiB}$、$\mathrm{MiB}$、$\mathrm{GiB}$、$\mathrm{TiB}$ 等，例如 $1\mathrm{KiB}=2^{10}\mathrm{B}=1024\mathrm{B}$；按十的幂计量的量仍用 $\mathrm{kB}$、$\mathrm{MB}$、$\mathrm{GB}$，例如 $\mathrm{kHz}$、$\mathrm{MHz}$、$\mathrm{kB/s}$、$\mathrm{MB/s}$、$\mathrm{GFLOPS}$ 等，例如 $1\mathrm{kB}=10^3\mathrm{B}$、$1\mathrm{MHz}=10^6\mathrm{Hz}$。很多书籍和软件也经常不区分二的幂和十的幂的表示，请读者朋友们注意区分。

### 基准程序

**基准程序**（benchmark）是一组用于评测性能的代表性程序。让不同系统处理相同任务，再比较执行时间，可以把指令集、编译器、CPU 和存储系统的影响放到同一个实际工作过程中观察。

基准程序测评也有其局限性：其性能常依赖于某些关键代码片段。硬件或编译器开发者可能对此
进行针对性优化，使这些片段执行极快，却无法代表系统处理一般负载的能力，导致评测结果失
真。

选择基准时，应让负载接近关注的应用：计算密集、访存密集和 I/O 密集程序对系统提出的要求各不相同。报告结果时还应保留程序输入、编译选项和测量范围；针对某段热点代码的优化，其收益也主要体现在具有相应特点的负载中。
