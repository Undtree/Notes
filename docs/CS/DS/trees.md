# 树

树是一种表示 **层次关系** 的非线性数据结构。在线性表中，一个元素最多有一个直接后继；而在树中，一个节点可以拥有多个子节点。目录结构、表达式和优先队列都可以用树来组织。

## 基本概念与存储结构

### 树的定义与术语

一棵树可以递归地定义为：空树，或者由一个 **根节点 (Root)** 和若干棵互不相交的非空子树组成的结构。每棵子树的根节点通过一条边与根节点相连。

-   **父节点与子节点**：直接相连的上下两层节点构成父子关系。除根节点外，每个节点恰有一个父节点。
-   **兄弟节点**：具有同一个父节点的节点。
-   **祖先与后代**：从根到某节点的路径上，该节点之前的节点是它的祖先；反过来，该节点是这些祖先的后代。
-   **节点的度 (Degree)**：该节点拥有的子节点数，也就是非空子树数。
-   **树的度**：树中所有节点的度的最大值。
-   **叶节点 (Leaf)**：度为 0 的节点；度大于 0 的节点称为分支节点。
-   **森林 (Forest)**：若干棵互不相交的树的集合。删除一棵非空树的根节点后，剩下的各棵子树构成森林。

对于一棵含有 $n$ 个节点的非空树，除根节点外，每个节点都对应一条连接其父节点的边，所以 **边数恰为 $n-1$**。同时，各节点的度数之和也等于 $n-1$。

!!! Note "深度、高度与层数的约定"
    本文沿用按 **边数** 计数的约定：

    -   节点的 **深度 (Depth)** 是根到该节点的路径长度，根节点深度为 0。
    -   节点的 **高度 (Height)** 是该节点到其子树内最远叶节点的路径长度，叶节点高度为 0。
    -   树高等于根节点高度，也等于所有节点深度的最大值。
    -   根位于第 1 层，因此节点层号等于深度加 1，非空树的总层数等于树高加 1。

    若题目或教材按层数定义树高，应将本文的边数树高加 1 后使用对应公式。

### 孩子兄弟表示法

一般树中各节点的子节点数不同，若为每个节点预留大量孩子指针，会浪费空间。**孩子兄弟表示法 (First-Child, Next-Sibling)** 为每个节点设置两个指针：

1. `FirstChild`：指向该节点的第一个子节点；没有子节点时为空。
2. `NextSibling`：指向该节点的下一个兄弟节点；没有后续兄弟时为空。

这样，从 `FirstChild` 出发沿 `NextSibling` 即可遍历某节点的所有孩子。将这两个指针分别看作左、右指针，就得到一般树的二叉链表表示。

森林也可以用相同方式表示：将各棵树的根节点按兄弟关系连接，再分别连接其孩子。转换保留了原来的父子与兄弟关系，但二叉表示中的右指针代表的是 **兄弟**，而非原树中的子节点。

## 二叉树与遍历

### 二叉树的定义与性质

**二叉树 (Binary Tree)** 是每个节点至多有两个子节点，并且区分 **左子树** 与 **右子树** 的树。即使一个节点只有一个孩子，也需要区分它是左孩子还是右孩子。

按照根位于第 1 层、树高按边数计算的约定：

-   第 $i$ 层最多有 $2^{i-1}$ 个节点，其中 $i\ge 1$。
-   高度为 $h$ 的二叉树最多有 $2^{h+1}-1$ 个节点。
-   对于非空二叉树，若度为 0、1、2 的节点数分别为 $n_0,n_1,n_2$，则 **$n_0=n_2+1$**。

??? Tip "$n_0=n_2+1$ 的推导"
    由节点数和边数的关系：

    $$
    n=n_0+n_1+n_2,\qquad n-1=n_1+2n_2.
    $$

    两式相减，即得 $n_0=n_2+1$。

两类常见的特殊二叉树是：

-   **满二叉树**：每一层都达到最大节点数。高度为 $h$ 时共有 $2^{h+1}-1$ 个节点。
-   **完全二叉树**：除最后一层外，其余各层均达到最大节点数，且最后一层的节点从左到右连续排列。

非空完全二叉树有 $n$ 个节点时，其高度为 $\lfloor\log_2 n\rfloor$。满二叉树一定是完全二叉树。

!!! Note "二叉树的顺序存储"
    将完全二叉树按层序从 1 开始编号，编号为 $i$ 的节点，其父节点编号为 $\lfloor i/2\rfloor$（$i>1$）；左、右孩子编号分别为 $2i$、$2i+1$，编号超过 $n$ 时表示对应孩子不存在。

    因此完全二叉树适合用数组紧凑存储。一般二叉树若采用相同编号方式，需要为缺失节点保留位置；链式存储通常更灵活。

### 二叉树的遍历

**遍历** 是按照某种次序访问树中的所有节点，且每个节点恰好访问一次。三种深度优先遍历的区别在于访问根节点的时机：

1. **先序遍历 (Preorder)**：根节点 → 左子树 → 右子树，也称前序遍历。
2. **中序遍历 (Inorder)**：左子树 → 根节点 → 右子树。
3. **后序遍历 (Postorder)**：左子树 → 右子树 → 根节点。

这三种遍历都可以递归实现，也可以用显式栈保存尚未完成的访问状态。含 $n$ 个节点、高度为 $h$ 的树，遍历时间为 $O(n)$，递归栈的辅助空间为 $O(h+1)$；树退化成单支时为 $O(n)$。

**层序遍历 (Level Order)** 则从上到下、同层从左到右访问节点，通常借助队列：

1. 若树非空，将根节点入队。
2. 取出队首节点并访问，将其非空左、右孩子依次入队。
3. 重复步骤 2，直到队列为空。

层序遍历的时间复杂度为 $O(n)$，队列的辅助空间在最坏情况下为 $O(n)$。

#### 表达式树

**表达式树 (Expression Tree)** 用叶节点表示操作数，用内部节点表示运算符。对于二元运算符，左、右子树分别表示左、右操作数对应的表达式。

-   先序遍历得到前缀表达式。
-   中序遍历结合必要的括号，得到保持原运算次序的中缀表达式。
-   后序遍历得到后缀表达式，可以用栈求值。

例如，表示 $(a+b)\times c$ 的树以 `*` 为根，左子树表示 `a+b`，右孩子为 `c`。其后缀表达式为 `a b + c *`；中缀形式需要保留括号，以区别于 $a+b\times c$。

### 线索二叉树

在非空二叉树的二叉链表中，$n$ 个节点共有 $2n$ 个孩子指针域，而非空链接只有 $n-1$ 个，所以共有 **$n+1$ 个空指针域**。**线索二叉树 (Threaded Binary Tree)** 利用这些空指针保存某种遍历次序下的前驱或后继。

以中序线索化为例：

-   若某节点没有左孩子，则让左指针指向其中序前驱。
-   若某节点没有右孩子，则让右指针指向其中序后继。
-   增加 `ltag`、`rtag` 等标志，区分指针指向的是 **孩子** 还是 **线索**。

在不设置头节点的实现中，第一个节点的前驱线索和最后一个节点的后继线索为空。若设置头节点，也可以让边界线索指向头节点。

对一个节点寻找中序后继时：若右指针是线索，直接沿线索访问；若右指针指向右子树，则进入右子树，再沿左孩子指针找到其中序第一个节点。这样便可以按中序遍历整棵树，无需递归或辅助栈，时间为 $O(n)$、额外空间为 $O(1)$。

## 二叉搜索树

### 定义与基本操作

**二叉搜索树 (Binary Search Tree, BST)** 也称二叉排序树。这里按关键字互不相同讨论：一棵非空 BST 的左子树中所有关键字均小于根节点，右子树中所有关键字均大于根节点，且左右子树也分别是 BST。

因此，**对 BST 进行中序遍历可以得到递增的关键字序列**。它的基本操作都利用这一有序关系：

-   **查找**：从根开始比较，目标值较小则进入左子树，较大则进入右子树，相等则成功；走到空指针时失败。
-   **查找最小值、最大值**：分别持续沿左孩子、右孩子访问，直到对应孩子为空。
-   **插入**：按查找路径定位空指针，在此处接入新节点。新节点插入时是叶节点。
-   **删除**：根据待删节点的孩子数分类处理。
    1. **没有孩子**：将父节点中指向它的链接置空，再释放节点。
    2. **只有一个孩子**：用其唯一的非空子树替代它。
    3. **有两个孩子**：用左子树最大节点（中序前驱）或右子树最小节点（中序后继）的记录替换当前记录，再从原位置删除那个替代节点。替代节点至多只有一个孩子，因而转化为前两种情况。

删除根节点时，需要相应更新树的根指针。相关查找分析及 AVL 树、红黑树等扩展，见 [查找：树形查找](./search.md#树形查找)。

### 懒惰删除

**懒惰删除 (Lazy Deletion)** 为节点增加删除标记，逻辑删除时只设置标记，暂时保留节点和链接。若以后重新插入相同关键字，可以直接恢复该节点。

这种方式将结构调整推迟到后续清理阶段。查找、遍历和最值查询需要忽略已标记记录；已删除节点仍然占用空间，也仍可能位于查找路径上，因此需要在适当时机回收或重建。

### 操作的时间复杂度

BST 的基本操作沿树中的一条路径进行，时间复杂度为 $O(h+1)$，其中 $h$ 为树高。

-   树形平衡时，$h=O(\log n)$，基本操作为 $O(\log n)$。
-   若不同关键字按等概率随机排列依次插入，基本操作的期望时间为 $O(\log n)$。
-   若关键字按递增或递减次序插入，树会退化成单支，高度为 $n-1$，基本操作退化为 $O(n)$。

因此，要在动态插入和删除后仍保持对数级的最坏时间，需要进一步维护树的平衡。

## 优先队列与二叉堆

### 优先队列的基本操作

普通队列按进入次序取出元素，**优先队列 (Priority Queue)** 则按优先级取出元素。以关键字越小、优先级越高的最小优先队列为例，核心操作是：

-   `Insert`：插入一个元素。
-   `FindMin`：读取最小元素。
-   `DeleteMin`：删除并返回最小元素。

优先队列描述的是操作规则，其内部元素无需始终按全序排列。不同实现有不同的开销：

-   **无序数组**：容量足够时，末尾插入为 $O(1)$；删除最小值需扫描数组，为 $O(n)$。找到后可以用末尾元素填补空位。
-   **无序链表**：表头插入为 $O(1)$；删除最小值需扫描链表，为 $O(n)$。
-   **有序数组**：插入时最坏需移动 $O(n)$ 个元素；若将最小元素放在数组末尾，删除最小值为 $O(1)$。
-   **平衡二叉搜索树**：插入和删除最小值均可在 $O(\log n)$ 时间内完成。

若主要需要插入和取最值，可以用结构更紧凑的 **二叉堆** 实现。

### 二叉堆的两个性质

**二叉堆 (Binary Heap)** 同时满足结构性质和堆序性质。

1. **结构性质**：二叉堆是一棵完全二叉树，因此可以用数组按层序存储。本文将元素存放在 `H[1...n]` 中，父节点、左孩子和右孩子的下标分别为 $\lfloor i/2\rfloor$、$2i$、$2i+1$。
2. **堆序性质 (Heap Order Property)**：最小堆中，每个父节点的关键字不大于其孩子的关键字。因此根节点就是全堆的最小元素。最大堆则反过来维护父节点不小于孩子。

对于非空堆，高度 $h$ 与节点数 $n$ 满足：

$$
2^h\le n\le 2^{h+1}-1,\qquad h=\lfloor\log_2 n\rfloor.
$$

!!! Note "堆序与全局有序"
    堆序约束父子关系，兄弟节点之间、不同子树之间可以无序。因此读取根节点的最值只需 $O(1)$，而查找某个任意关键字在最坏情况下仍需扫描 $O(n)$ 个元素。

### 二叉堆的基本操作

#### 插入与上滤

向最小堆插入元素时，先将新元素放到数组末尾，保持完全二叉树的结构。若它小于父节点，就与父节点交换，并继续向上比较，直到堆序恢复或到达根节点。这个过程称为 **上滤 (Percolate Up)**。

上滤最多经过一条从叶到根的路径。在数组容量足够时，插入的最坏时间复杂度为 $O(\log n)$。

#### 删除最小值与下滤

删除最小堆的根节点后，将末尾元素移到根位置，并将堆的元素个数减 1。随后：

1. 在当前节点的现有孩子中选取关键字较小者。
2. 若当前节点不大于该孩子，调整结束。
3. 否则交换两者，继续向下调整。

这个过程称为 **下滤 (Percolate Down)**。只剩一个孩子时与该孩子比较；到达叶节点时结束。删除最小值的最坏时间复杂度为 $O(\log n)$。若原来只有一个元素，删除后直接得到空堆。

### 修改关键字与删除指定元素

以下操作假设已经知道元素在堆数组中的位置 $p$：

-   **`DecreaseKey`**：将关键字减小后，可能破坏它与父节点之间的堆序，应执行上滤。
-   **`IncreaseKey`**：将关键字增大后，可能破坏它与孩子之间的堆序，应执行下滤。
-   **删除位置 $p$ 的元素**：将末尾元素移到 $p$，缩小堆；若替代元素小于父节点，则上滤，否则下滤。删除的本来就是末尾元素时，无需调整。

三者最坏均为 $O(\log n)$。另一种删除思路是把目标关键字降为小于其他所有元素的值，将其上滤到根，再执行 `DeleteMin`；这要求关键字表示支持合适的哨兵值。

!!! Tip "如何持续定位一个元素"
    堆调整会改变元素下标。若需要按元素编号频繁修改优先级，可以额外维护“元素编号 → 堆中位置”的映射，并在交换元素时同步更新。这样才能在定位后直接执行上滤或下滤。

调度器可以用优先队列维护就绪任务。当采用“关键字越小、优先级越高”的约定时，提高优先级对应减小关键字，降低优先级对应增大关键字；具体映射由调度策略决定。

### 线性建堆

对 $n$ 个现成元素逐个执行插入，最坏需要 $O(n\log n)$ 时间。更直接的 **建堆 (BuildHeap)** 方法是先将所有元素放入数组，再从最后一个非叶节点 $\lfloor n/2\rfloor$ 开始，按下标递减的顺序逐个执行下滤。

处理某个节点时，它的左右子树已经分别满足堆序，只需通过一次下滤修复以该节点为根的堆。

??? Tip "为什么建堆只需要 $O(n)$？"
    接近叶层的节点最多，但能够下滤的距离最短；高度较大的节点较少。高度为 $k$ 的节点数至多为 $n/2^k$，每个节点最多下滤 $k$ 层，因此总工作量满足：

    $$
    O\left(\sum_{k=1}^{\lfloor\log_2 n\rfloor}\frac{n}{2^k}\,k\right)
    =O\left(n\sum_{k=1}^{\infty}\frac{k}{2^k}\right)
    =O(n).
    $$

    分析的关键是按节点高度累加实际调整上界，而非给每个节点都计入一次完整树高。

### 应用与多叉堆

优先队列可用于任务调度、最短路径算法，以及选择问题。例如，要找 $n$ 个元素中第 $k$ 大的元素（$1\le k\le n$），可以维护一个至多含 $k$ 个元素的最小堆：先对前 $k$ 个元素建堆，随后只在新元素大于堆顶时替换堆顶并下滤。最终堆内保存最大的 $k$ 个元素，堆顶就是第 $k$ 大的值。时间上界为 $O(n\log(k+1))$，额外空间为 $O(k)$；$k=1$ 时相当于线性扫描最大值。

**$d$ 叉堆 ($d$-ary Heap)** 将每个节点的孩子数上限扩展为 $d$（$d\ge 2$），仍按层序从左到右紧凑存储：

-   高度降为 $O(\log_d n)$，插入只需沿父节点方向上滤，时间为 $O(\log_d n)$。
-   删除最小值时，每层需要在至多 $d$ 个孩子中选出最小者，最坏时间为 $O(d\log_d n)$。

增大 $d$ 减少了路径长度，同时增加了每层选择孩子的比较次数。若用于外存，还需要结合块大小和节点布局考虑 I/O 开销。

## 并查集

**并查集 (Disjoint Set Union, DSU)** 用于维护若干个互不相交的集合，支持两个核心操作：

-   **`Find(x)`**：找到元素 $x$ 所属集合的代表元。
-   **`Union(x, y)`**：合并 $x$、$y$ 所属的集合；若二者已经属于同一集合，则保持不变。

### 森林表示

并查集通常用一片森林表示，每个集合对应一棵树，根节点作为代表元。数组 `parent[x]` 保存父节点编号，根节点满足 `parent[x] = x`。

初始化时，每个元素单独构成一个集合。查找时沿父指针上行直到根节点；合并时先找到两个根，再将其中一个根连接到另一个根下。

如果任意选择合并方向，树可能退化成链，单次查找最坏为 $O(n)$。常见的改进有：

1. **按规模合并**：用 `size` 记录集合大小，将较小集合的根接到较大集合的根下。一个元素深度每增加 1，其所在集合大小至少翻倍，因此单次查找为 $O(\log n)$。
2. **按秩合并**：用秩估计树高，将低秩根接到高秩根下；秩相同则任选一个根作为父节点，并将其秩加 1。
3. **路径压缩**：执行 `Find` 找到根后，让沿途节点直接指向根，缩短以后的查找路径。

按规模或按秩合并配合路径压缩后，初始化 $n$ 个元素并执行 $q$ 次查找、合并操作的总时间可写为 $O(n+q\alpha(n))$，其中 $\alpha$ 是增长极其缓慢的反阿克曼函数，辅助空间为 $O(n)$。

### 连通性应用

在无向图中，可以让每个顶点初始各自成一个集合。每处理一条边，就合并两个端点所在的集合；两点的代表元相同，表示它们已经连通。

[Kruskal 算法](./graph.md#最小生成树) 正是利用这一点判断是否成环：若一条候选边的两个端点已在同一集合中，加入该边会形成环，应跳过；否则接纳该边并合并两个集合。
