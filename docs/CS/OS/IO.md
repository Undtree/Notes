# 输入/输出

I/O 是计算机与外部世界交换信息的通道。键盘、显示器、磁盘、打印机和网卡的工作方式各不相同，速度也往往与 CPU 相差很大。操作系统需要把这些差异封装起来，让应用程序能够通过统一接口使用设备，同时协调数据传输、设备共享与错误处理。

这一章先从设备与控制方式出发，建立 I/O 软件的层次，再讨论缓冲、设备分配与假脱机，最后介绍磁盘和固态硬盘的管理。

## I/O 管理概述

### I/O 设备

一个 I/O 设备通常包括 **设备本身** 和 **设备控制器**：前者完成实际的输入或输出，后者连接主机与设备，接收命令、报告状态并组织数据交换。例如，磁盘的盘片与磁头负责记录和读取信息，控制器负责解释读写请求并协调操作。

#### 设备的分类

分类时要明确采用的标准，同一设备可以同时属于多个类别。

<center markdown="1">

| 分类依据 | 类别 | 特点与例子 |
| :---: | :---: | :---: |
| 信息交换单位 | 块设备 | 按数据块交换，通常可寻址和随机访问，如磁盘 |
| 信息交换单位 | 字符设备 | 按字符或字节交换，通常按流顺序访问，如键盘、终端、打印机 |
| 传输速率 | 低速、中速、高速设备 | 教材分别以键盘、打印机、磁盘等为例，划分描述的是相对速度 |
| 使用特性 | 人机交互设备 | 在用户与计算机之间传递信息，如键盘、显示器 |
| 使用特性 | 存储设备 | 保存程序与数据，如磁盘、磁带、光盘 |
| 使用特性 | 网络通信设备 | 在计算机之间传递信息，如网卡、调制解调器 |
| 共享属性 | 独占设备 | 分配后由一个进程使用，结束后再交给其他进程，如打印机 |
| 共享属性 | 共享设备 | 可供多个进程在逻辑上并发使用，由系统协调物理访问，如磁盘 |
| 共享属性 | 虚拟设备 | 借助共享存储和软件，把独占设备表现为多个逻辑设备，见 [SPOOLing](#spooling-技术假脱机技术) |

</center>

“块设备可随机访问”表示能够指定目标块，不能据此认为访问任意块的耗时完全相同。共享设备的“同时使用”通常也是逻辑上的并发，具体传输仍需要调度。

#### I/O 接口

这里的 **I/O 接口** 指硬件上的设备控制器。它与后面的[应用程序 I/O 接口](#应用程序-io-接口)不是同一层次。

控制器主要包括三部分：

1.  **与 CPU 的接口**。通过地址线选择端口，通过数据线交换数据、命令和状态，通过控制线确定读写等操作。
2.  **与设备的接口**。传递设备一侧的数据、控制和状态信号，一个控制器可以连接一个或多个设备。
3.  **I/O 逻辑**。识别地址、解释命令，并按设备状态组织操作。

控制器的主要功能包括接收和识别命令、数据交换、报告状态、地址识别、数据缓冲和差错控制。设备驱动程序向它写入参数和命令，读取状态或结果，不必由应用程序直接操作设备。

硬件信号与寄存器的进一步说明，见[计算机组成中的 I/O 接口](../CO/co_IO.md#io接口)。

#### I/O 接口的类型

可以从不同角度分类：

-   按设备侧的数据传送方式，分为 **串行接口** 与 **并行接口**，必要时完成串并格式转换。
-   按主机控制传送的方式，分为程序查询接口、中断接口和 DMA 接口等。
-   按功能能否通过编程改变，分为可编程与不可编程接口。
-   按所连接的设备类型，分为字符设备、块设备和网络设备接口。

这些分类可以组合。例如，串行传输描述数据如何经过连接线路，DMA 描述谁负责搬运数据，二者并不互斥。

#### I/O 端口

在这里，**端口** 是控制器中可由 CPU 访问的寄存器，而不是设备外部插口或网络通信中的端口号。

<center markdown="1">

| 端口类型 | 主要用途 | 常见访问方向 |
| :---: | :---: | :---: |
| 数据寄存器 | 暂存输入或输出数据 | CPU 读取输入，写入输出 |
| 状态寄存器 | 保存忙闲、就绪、完成和错误等状态 | CPU 读取 |
| 控制寄存器 | 设置工作方式、提交启动命令 | CPU 写入 |

</center>

CPU 访问端口时，需要识别其地址，主要有两种编址方式。

<center markdown="1">

| 方式 | 地址空间与访问指令 | 主要取舍 |
| :---: | :---: | :---: |
| 独立编址，I/O 映射 | 端口与主存属于不同地址空间，使用专用 I/O 指令，如 `IN`、`OUT` | I/O 操作易于辨认，端口译码可以较简单，但需要相应指令和控制信号 |
| 统一编址，内存映射 I/O | 端口占用存储器地址空间中的部分地址，使用普通加载、存储指令 | 便于利用访存指令和地址保护机制，但需要识别设备地址范围 |

</center>

统一编址占用的是 **地址空间**，不能理解为把设备寄存器的数据存进普通 RAM。它与[内存映射文件](./memory.md#内存映射文件)也不同：前者映射硬件端口，后者映射文件内容。

### I/O 控制方式

控制方式的发展方向，是减少 CPU 在等待、搬运和组织 I/O 时的干预。比较时应分别观察：**谁检查设备状态，谁搬运数据，CPU 多久介入一次**。

#### 程序直接控制方式

也称程序轮询方式。在教材的持续轮询模型中，CPU 启动设备后反复读取状态寄存器；就绪时从数据端口取出一个字或字节，再写入主存，更新地址和计数，继续处理后续数据。输出时方向相反。

这种方式控制简单，但状态检查和数据搬运都由 CPU 执行。持续忙等待占用 CPU，使设备准备数据的时间难以用于其他有用计算。

程序查询也可以采用间隔查询，不能把所有轮询都理解为持续占用 CPU。两种查询策略及开销计算，见[程序查询方式](../CO/co_IO.md#程序查询方式)。

#### 中断驱动方式

CPU 发出 I/O 命令后，可以执行其他工作；设备准备好数据或需要服务时，通过中断通知 CPU。随后由中断处理程序检查状态，并完成相应的数据搬运或后续处理。

在逐字或逐字节传送的模型中，数据仍经过 CPU 寄存器，中断服务也需要执行指令和保护现场，因此高速、大批量传输会带来较高开销。

中断的基本分类与响应过程见[中断机制](./os_intro.md#int)。I/O 完成中断如何处理请求进程，见[本章的中断处理程序](#中断处理程序)。

#### DMA 方式

**DMA（Direct Memory Access，直接存储器访问）** 由控制器在设备与主存之间搬运数据。CPU 设置传输方向、主存起始地址、长度等参数，启动传输，完成后再处理结果。

DMA 控制器的基本寄存器包括：

<center markdown="1">

| 寄存器 | 作用 |
| :---: | :---: |
| 命令／状态寄存器 CR | 保存传输命令与状态 |
| 内存地址寄存器 MAR | 保存当前主存传输位置，初值为起始地址 |
| 数据寄存器 DR | 暂存传输的数据单元 |
| 数据计数器 DC | 记录传输数量，随传送更新 |

</center>

DMA 的基本特点是以数据块组织传输、数据不经过 CPU 通用寄存器、CPU 主要在开始和结束时介入。块内仍可以逐字搬运，完成时通常通过中断通知 CPU。

DMA 仍需使用总线和主存，可能与 CPU 访存竞争。突发传送、周期挪用等方式，见[DMA 的传送方式](../CO/co_IO.md#dma的传送方式)；不能把“无需 CPU 逐字搬运”理解为“对 CPU 完全没有影响”。

#### 通道控制方式

**I/O 通道** 是面向 I/O 的专用处理机，能够执行存放在主存中的通道程序。CPU 指明设备和通道程序位置后，由通道按程序组织操作，结束时报告结果。

与一次设置一个数据块的 DMA 模型相比，通道可以执行一系列专用指令，自主组织多个阶段、多个设备的操作。它的指令功能以 I/O 为主，不能当作通用 CPU 使用。

<center markdown="1">

| 控制方式 | 数据搬运与操作组织 | CPU 的主要介入方式 |
| :---: | :---: | :---: |
| 程序直接控制 | CPU 查询并搬运 | 逐字或逐字节查询、传送 |
| 中断驱动 | CPU 在中断服务中搬运 | 按设备服务事件介入，教材模型中通常逐字或逐字节 |
| DMA | 控制器直接在设备与主存间传送 | 设置数据块，处理完成通知 |
| 通道 | 通道执行程序组织 I/O | 启动通道程序，处理最终结果 |

</center>

### I/O 软件层次结构

I/O 软件把设备特定的操作与各类设备共用的功能分开，常见结构由上到下是：

$$
\text{用户层软件}\longrightarrow\text{设备独立性软件}
\longrightarrow\text{设备驱动程序}\longrightarrow\text{中断处理程序}
$$

设备硬件位于这些软件层之下。分层描述的是功能，实际系统中各层边界可能有所调整；中断处理通常也与驱动程序密切配合。

#### 用户层软件

包括与应用程序链接的 I/O 库函数，负责格式化、用户缓冲和提供便利接口，例如 `printf()`、`scanf()`。需要内核服务时，再通过[系统调用](./os_intro.md#syscall)进入内核。

调用库函数本身不一定立刻发生系统调用。例如，格式化结果可能先写入库管理的缓冲区，之后再统一提交。

#### 设备独立性软件

**设备独立性**，也称设备无关性，是应用程序不必绑定某一台具体物理设备。程序使用逻辑设备名，系统负责选择物理设备并定位驱动程序，因而可以支持重定向和设备替换。

这一层提供公共 I/O 服务和统一接口，其具体职责集中在[设备独立性软件的公共功能](#device-independent-functions)中说明；逻辑名到物理名的映射见[逻辑设备表](#逻辑设备名到物理设备名的映射)。

#### 设备驱动程序

驱动程序是与设备特性直接相关的软件，负责把上层的抽象请求转换为控制器能执行的命令，并反馈结果。它与硬件控制器不同：一个是程序，一个是电路。

请求检查、寄存器设置、启动和接口规范，见[设备驱动程序接口](#设备驱动程序接口)。

#### 中断处理程序

I/O 中断到达时，CPU 可能正在运行另一个进程。保护现场等通用过程见[中断的处理](./os_intro.md#中断的处理)，这里关注设备服务：

1.  确认中断来源，读取设备状态，判断是正常完成、需要继续传输，还是发生错误。
2.  执行必要的设备操作，处理或清除中断标志。程序中断 I/O 可能需要搬运数据；DMA 完成时数据已经由控制器搬运。
3.  更新请求状态；若等待条件已满足，则唤醒等待进程，并安排后续请求。

!!! tip "请求进程与被中断进程"

    发起阻塞 I/O 的进程 P 正在等待时，CPU 可以运行进程 Q。设备完成后，中断打断的可能是 Q；处理程序把 P 从阻塞态变为就绪态，P 需要再次被调度才会运行。

    中断到达并不表示 P 已经运行，也不能把保存 Q 的现场理解为重新保存 P 的现场。状态变化见[进程的阻塞和唤醒](./process.md#进程的阻塞和唤醒)。

驱动初始化时需要注册中断号和处理函数，停用时注销；共享中断线时，要识别是否由本设备引发，不能影响其他设备的处理例程。

常规硬件中断处理应尽快完成，不能执行需要睡眠等待的操作。要把中断处理本身与被唤醒进程恢复执行后的工作区分开。

#### I/O 操作举例 <a id="io-layer-example"></a>

以一次确实需要访问设备的阻塞写请求为例，可以从软件层次观察：

1.  用户层准备数据，通过系统调用接口提交描述符、缓冲区地址与长度。
2.  设备独立性层检查参数和访问权限，处理公共缓冲与设备定位。
3.  驱动程序把请求转换为设备命令，设置参数并启动硬件。
4.  请求进程等待，CPU 调度其他就绪进程。
5.  设备完成后触发中断，处理程序更新状态并唤醒等待者。
6.  请求进程再次运行，完成系统调用的后续处理，再返回用户态。

这里只讨论指定的阻塞路径。若请求可以由缓冲立即满足，或采用其他接口模式，就不一定经过等待设备的全部步骤。缓冲数据如何流入用户变量，见后面的[键盘输入示例](#keyboard-input)。

### 应用程序 I/O 接口

操作系统通过系统调用与软件接口封装设备差异。接口可以按数据交换单位、寻址能力、共享方式、输入输出方向等组织；这些属性与[设备分类](#设备的分类)相对应。

#### I/O 接口的分类

<center markdown="1">

| 接口 | 对上层提供的主要操作 | 封装的设备差异 |
| :---: | :---: | :---: |
| 字符设备接口 | 字符读取、写入，如抽象的 `get`、`put`，以及打开、关闭和设备控制 | 字符流、缓冲和具体工作模式 |
| 块设备接口 | 块读取、写入和定位，如 `read`、`write`、`seek` | 将块号组织为线性地址，隐藏实际物理布局 |
| 网络设备接口 | 通过套接字（Socket）建立通信端点，发送与接收数据 | 网络协议、通信端点与底层网卡操作 |

</center>

字符设备的特殊功能可以通过 `ioctl` 一类设备控制接口设置。统一接口不表示所有设备都支持完全相同的控制操作，也不表示 `ioctl` 取代了普通读写。

#### 阻塞 I/O 和非阻塞 I/O

**阻塞 I/O** 在请求暂时无法完成时，使调用进程等待。条件满足后进程进入就绪态，再次获得 CPU 后继续执行并取得结果。如果请求立即可满足，则未必发生阻塞。

**非阻塞 I/O** 在当前条件下尽可能完成操作，并及时返回。没有可用数据或空间时，可以返回暂时不可完成的状态；也可能只完成部分传输，程序需要依据实际结果继续处理。

<center markdown="1">

| 模式 | 暂时不能完成时 | 程序需要关注的事 |
| :---: | :---: | :---: |
| 阻塞 | 等待条件满足 | 控制流程直接，但该调用进程不能继续做其他工作 |
| 非阻塞 | 返回当前结果或暂时不可完成状态 | 处理重试和部分传输，避免无意义地反复查询 |

</center>

!!! note "进程阻塞不等于 CPU 空闲"

    阻塞的是发起请求的执行实体，操作系统仍可调度其他就绪进程。非阻塞接口也不表示底层不用中断或 DMA：接口是否等待，与硬件怎样传送数据，是不同的划分。

## 设备独立性软件

### 设备独立性软件 <a id="device-independent-functions"></a>

在前面的[层次结构](#io-软件层次结构)中，这一层位于驱动之上，集中实现设备的公共操作。具体功能包括：

1.  **统一驱动接口与设备映射**。根据抽象名称定位设备及驱动，向上提供一致的调用方式。
2.  **缓冲管理**。协调速度差异和数据粒度，组织[高速缓存与缓冲区](#高速缓存与缓冲区)。
3.  **差错控制**。暂时性错误可以尝试重做；超过重试限制或无法恢复时，上报失败。驱动能处理的底层错误由驱动处理，共性错误和后续策略由上层协调。
4.  **独占设备的分配与回收**。维护状态与等待队列，防止多个进程无序争用，具体见[设备分配](#设备分配与回收)。
5.  **提供统一的逻辑数据块**。使上层可以使用统一抽象，不必逐个适应设备的物理交换单位。
6.  **设备保护**。检查访问权限，确保硬件通过内核受控路径使用。

逻辑数据块与设备物理块并不必然等大，必要时要进行分块、组合或缓冲。统一接口也不消除硬件差异，而是把这些差异留给对应驱动处理。

### 高速缓存与缓冲区

#### 磁盘高速缓存

**磁盘高速缓存（Disk Cache）** 使用主存保存磁盘数据的副本，使重复读取能够由内存直接满足，也便于暂存修改和合并写入。

它可以使用固定的专用空间，也可以采用动态缓冲池，与其他内存需求共同使用可用页框。其依据是[局部性](./memory.md#locality)，与 CPU 内部的硬件 Cache 处于不同层次。

缓存命中时可以减少实际磁盘访问；未命中时才需要安排读取。对于被修改的内容，还要维护它与外存副本的关系，写回优化见[提高磁盘 I/O 速度的方法](#提高磁盘-io-速度的方法)。

#### 缓冲区

**缓冲区（Buffer）** 暂存正在传输的数据，主要用于缓和速度差异、降低服务或中断频率、匹配数据粒度，并提高设备与处理过程的并行程度。缓冲可以由硬件提供，也可以在主存中分配。

**单缓冲**。

设一次输入处理包含三个阶段：设备把一块数据输入缓冲区，耗时 $T$；从缓冲区送到用户工作区，耗时 $M$；CPU 在工作区处理数据，耗时 $C$。本节采用整块输入后才能移出、只有一个用户工作区的模型。

单缓冲中，移出当前数据后，设备输入下一块可以与 CPU 处理当前块并行；但移出操作不能与同一缓冲区的写入重叠，也不能覆盖仍在处理的工作区。因此稳态下每块的周期为：

$$
\tau_{\mathrm{single}}=\max(T,C)+M
$$

**双缓冲**。

设备填充一个缓冲区时，系统可以从另一个满缓冲区移出数据并处理，两个缓冲区交替使用。因此，在同样的工作区模型下：

$$
\tau_{\mathrm{double}}=\max(T,M+C)
$$

!!! tip "稳态周期与有限批次总时间"

    第一块必须先经过 $T+M+C$，不能把稳态周期直接当作第一块的完成时间。若开始时缓冲区和工作区均为空，连续输入 $n$ 块，并处理完最后一块，则在上述模型中：

    $$
    t_{\mathrm{single}}=T+M+C+(n-1)\bigl[\max(T,C)+M\bigr]
    $$

    $$
    t_{\mathrm{double}}=T+M+C+(n-1)\max(T,M+C)
    $$

    若题目规定初始已有数据、传送可以与其他阶段重叠，或者只要求完成输入，须按实际时间线重新计算。

例如，$T=10$ ms、$M=2$ ms、$C=6$ ms 时，单缓冲稳态周期为 12 ms，双缓冲为 10 ms；从空状态处理完三块分别需要 42 ms 与 38 ms。

双机通信中，若同一个缓冲区只能承担一种收发角色，单缓冲限制了双方同时收发；分别设置发送和接收缓冲区，才能支持相应的全双工流程。

**循环缓冲**。

把多个等大的缓冲区组织为循环队列，`in` 指向下一处写入位置，`out` 指向下一处读取位置。输入方推进 `in`，处理方推进 `out`：

-   缓冲全部填满时，输入方等待处理方释放空间。
-   缓冲全部为空时，处理方等待输入方提供数据。

只比较 `in == out` 不能同时区分满与空，还需结合计数或状态等约定。同步关系可按[生产者与消费者](./sync.md#生产者-消费者问题)理解。多个缓冲可以吸收一段时间的速度波动，但不能无限消除长期的供需差距。

**缓冲池**。

缓冲池由系统统一管理，供多个进程共享。按状态组织为 **空缓冲队列、输入队列和输出队列**，每个缓冲区在使用时承担相应角色。

<center markdown="1">

| 操作 | 缓冲区角色 | 获取来源 | 完成后去向 |
| :---: | :---: | :---: | :---: |
| 收容输入 | `hin` | 空缓冲队列 | 填入设备输入后，加入输入队列 |
| 提取输入 | `sin` | 输入队列 | 数据取走后，加入空缓冲队列 |
| 收容输出 | `hout` | 空缓冲队列 | 填入计算结果后，加入输出队列 |
| 提取输出 | `sout` | 输出队列 | 数据交给输出设备后，加入空缓冲队列 |

</center>

四种角色不要求永久对应四块固定内存。缓冲区从队列中取出后由当前操作使用，完成后再转入下一队列；操作队列与访问缓冲内容都需要适当同步。

#### 高速缓存与缓冲区的对比

<center markdown="1">

| 比较项 | 高速缓存 | 缓冲区 |
| :---: | :---: | :---: |
| 主要用途 | 利用已有副本，减少重复访问慢速介质 | 暂存传输中的数据，协调速度和数据粒度 |
| 典型使用方式 | 查找是否命中，保留可能再次使用的内容 | 填入、移出、释放或交给下一处理阶段 |
| 关注的性能 | 命中率与慢速介质访问次数 | 传输并行程度、等待和搬运成本 |

</center>

两者都使用较快存储空间缓解速度差异，也可以由同一片内存同时承担，区别主要在于 **使用目的**，不能仅凭存放位置判断。

### 设备分配与回收

#### 设备分配概述

设备分配根据进程的请求，安排设备及其访问通路。目标是在提高利用率的同时，避免不恰当的资源占用导致死锁。

独占设备需要明确占用与释放，共享设备需要协调并发请求，虚拟设备则通过[假脱机](#spooling-技术假脱机技术)安排提交和实际服务。设备属性本身见[设备的分类](#设备的分类)。

#### 设备分配的数据结构

教材采用“通道—控制器—设备”的模型。一个通道可以管理多个控制器，一个控制器可以连接多个设备，需要用控制表表达状态、从属关系和等待队列。

<center markdown="1">

| 表 | 管理对象 | 主要内容 |
| :---: | :---: | :---: |
| 设备控制表 DCT | 每台物理设备 | 类型、标识符、忙闲状态、控制器表指针、重试限制、设备等待队列 |
| 控制器控制表 COCT | 每个控制器 | 标识符、状态、通道表指针、控制器等待队列 |
| 通道控制表 CHCT | 每个通道 | 标识符、状态、所连接控制器的信息、通道等待队列 |
| 系统设备表 SDT | 全系统的物理设备索引 | 设备类型和标识符、DCT 指针、相应驱动信息 |

</center>

SDT 用来找到设备，DCT、COCT 和 CHCT 用来检查具体资源是否可用。这些表是内核数据结构，不是设备控制器中的硬件寄存器。

#### 设备分配时应考虑的因素

需要综合考虑设备固有属性、分配算法、安全性和[设备独立性](#设备独立性软件)。

常见分配算法包括 **先来先服务（FCFS）** 和 **最高优先级优先**；后者通常在优先级相同时按请求顺序处理。这里安排的是设备使用资格，与后面的[磁盘请求调度](#磁盘调度算法)关注点不同。

教材还区分两种分配方式：

-   **安全分配方式**。发出设备请求后等待本次操作结束，在等待期间不再继续申请其他设备，限制形成设备循环等待的机会。
-   **不安全分配方式**。发出请求后仍可继续运行、申请其他设备，只有资源暂不可用时才等待，允许更多并行，也可能形成循环等待。

“不安全”表示需要额外处理死锁风险，并非每次都发生死锁；“安全”也应放在教材的设备请求模型中理解，不能据此断言系统中任何资源都不可能死锁。相关条件见[死锁发生的条件](./sync.md#死锁发生的条件)。

安全方式限制的是同一请求进程的推进，不要求整个系统的 CPU 与所有设备串行工作。

#### 设备分配的步骤

在具有通道的独占设备模型中，基本顺序为：

$$
\mathrm{SDT}\longrightarrow\mathrm{DCT}\longrightarrow\mathrm{COCT}\longrightarrow\mathrm{CHCT}
$$

1.  **分配设备**。由 SDT 找到 DCT，检查设备状态；忙则加入设备等待队列，空闲则安排占用。
2.  **分配控制器**。由 DCT 找到 COCT；控制器忙则等待，可用则继续。
3.  **分配通道**。由 COCT 找到 CHCT；通道忙则等待，可用则完成通路分配，启动传输。

设备、控制器和通道都可用，才算完成这次分配。回收时需要释放相应资源、更新状态，并处理等待队列；无等待者时置为空闲，有等待者时根据策略安排后续请求。

若请求指定某台物理设备，该设备忙时只能等待。若请求使用逻辑设备名，则可在同类设备中选择可用者；所有候选都忙时，再加入对应类别的等待队列。

#### 逻辑设备名到物理设备名的映射

**逻辑设备表（Logical Unit Table，LUT）** 记录逻辑设备名、物理设备名和驱动程序入口。系统选定设备后建立映射，后续请求便通过它定位实际资源。

<center markdown="1">

| 设置方式 | 名称作用范围 | 适用特点 |
| :---: | :---: | :---: |
| 全系统共用一张 LUT | 教材模型中要求逻辑名在全系统不冲突 | 适合简单的单用户场景 |
| 各用户分别设置 LUT | 不同用户可以使用相同逻辑名 | 便于多用户使用，物理资源仍由全局 SDT 管理 |

</center>

LUT 解决“程序使用的名称对应什么”，SDT 解决“系统有哪些物理设备”。名称可以独立，并不意味着物理设备就没有竞争。

### SPOOLing 技术（假脱机技术）

**SPOOLing** 用磁盘作为暂存空间，以专门的软件进程模拟脱机输入输出的外围机功能。它仍由主机系统控制，所以称为 **假脱机**。早期脱机 I/O 的背景见[操作系统的发展](./os_intro.md#操作系统的任务执行设计)。

系统主要由四部分构成：

-   **输入井与输出井**。磁盘中的暂存区域，按文件保存输入数据和待输出结果，并组织请求队列。
-   **输入缓冲区与输出缓冲区**。主存中的中转空间，用于连接低速设备与磁盘井。
-   **输入进程与输出进程**。后台执行相应的数据搬运，模拟外围机。
-   **井管理程序**。组织用户作业与磁盘井之间的信息交换。

输入路径可以表示为“输入设备 → 输入缓冲区 → 输入井 → 用户处理”；输出路径则是“用户结果 → 输出井 → 输出缓冲区 → 输出设备”。**井在磁盘上，缓冲区在主存中**。

以打印为例：

1.  用户提交打印请求，系统在输出井中保存待打印数据，创建请求表并加入打印队列。
2.  提交完成后，用户进程可以继续执行，不必等待打印机把整份内容印出来。
3.  后台打印进程在打印机空闲时取出请求，把井文件内容经输出缓冲区交给打印机。
4.  当前任务完成后，再处理后续请求，释放相应暂存空间。

!!! tip "逻辑共享与物理输出"

    多个进程可以并发提交任务，各自获得独立的暂存空间，仿佛各有一台打印机；实际打印机仍按安排逐个输出。

    提交成功与纸面输出完成是两个时刻。SPOOLing 改善了提交等待与资源利用，并不会使打印机的机械打印速度变快。

其主要效果是缓和速度差异、把独占设备表现为可共享的虚拟设备，并提高计算与 I/O 的并行程度。这是以磁盘空间换取时间和使用灵活性的方式，需要多道程序与相应后台管理的支持。

### 设备驱动程序接口

驱动在[软件层次](#设备驱动程序)中的位置已经说明。这里集中观察上层请求如何变成设备操作，以及不同驱动怎样接入统一框架。

<center markdown="1">

| 工作 | 具体内容 |
| :---: | :---: |
| 转换命令与地址 | 将抽象读写、逻辑块等转换为控制器需要的命令和参数 |
| 检查请求 | 检查操作、范围和权限是否允许，如不能从只写设备读取 |
| 查询状态 | 确认设备是否就绪，暂不可用时安排排队或等待 |
| 传递参数与启动 | 设置方向、缓冲区地址和传输长度等，向控制器提交命令 |
| 完成与错误处理 | 配合中断处理，维护状态，反馈结果，必要时重试或上报失败 |

</center>

在传统磁盘几何模型中，地址转换可能涉及柱面、盘面和扇区；在向控制器提交线性块号的接口中，具体几何细节可以由控制器封装。因此，要按题目描述判断转换在哪一层完成。

驱动与设备类型和[I/O 控制方式](#io-控制方式)密切相关。为支持并发请求，应组织好可重入执行和共享状态的同步，不能让不同调用相互覆盖参数。

统一接口要求驱动遵守内核约定的调用规范，通过设备管理机制定位入口，并实施访问控制；这使新增设备主要通过对应驱动接入。设备初始化、状态维护和部分底层功能也可能与设备固件配合。

### I/O 操作举例 <a id="keyboard-input"></a>

以 `scanf("%d", &d)` 为例，重点观察字符如何进入变量，以及用户缓冲与内核缓冲如何衔接。请求穿过软件层次的通用过程见[前面的写操作示例](#io-layer-example)。

`scanf()` 是用户态库函数，先检查标准库管理的 **用户缓冲区**。若已有足够字符，可直接解析；若需要补充输入，再通过 `read` 请求内核服务。典型参数包括输入描述符 `fd`、接收数据的用户地址 `buf` 和最大读取长度 `count`。

在需要等待键盘输入的中断驱动模型中：

1.  系统调用进入内核，检查请求及可用输入；尚不满足读取条件时，进程 P 进入阻塞态。
2.  用户按键，字符到达键盘接口的数据端口，接口发出中断请求。
3.  键盘中断处理读取端口，把字符放入 **内核缓冲区**，更新输入状态。
4.  达到读取条件后唤醒 P，使其进入就绪队列。
5.  P 再次获得 CPU，系统调用继续，把数据从内核缓冲区复制到用户缓冲区，返回实际读取结果。
6.  `scanf()` 在用户态解析字符，把转换得到的整数存入变量 `d`。

$$
\text{键盘接口}\longrightarrow\text{内核缓冲区}
\longrightarrow\text{用户缓冲区}\xrightarrow{\text{解析}}d
$$

端口访问依赖设备，属于驱动及其配合的中断处理；从内核缓冲区向用户空间提供数据，则属于与具体设备无关的处理。整数转换由库函数完成，键盘中断不会直接把完整整数写进 `d`。

是否在一次按键后就返回，取决于接口的读取条件，不能把“收到一个字符”与“整次输入请求已满足”机械等同。

## 磁盘和固态硬盘

### 磁盘

机械磁盘用磁性盘面记录数据，盘片旋转，磁头沿径向移动。基本结构包括：

-   **盘片与盘面**。一个盘片可以有用于记录的表面，每个记录面对应磁头。
-   **磁道**。盘面上的同心圆记录区域。
-   **扇区**。磁道划分出的固定大小区域，是介质寻址与传输的基本单位。
-   **柱面**。各记录面上半径相同的磁道集合。

在活动头盘组模型中，磁头由同一磁头臂带动，处于同一个柱面。访问时先定位柱面，再选择盘面，等待目标扇区转到磁头下方，随后传输数据。

若每道扇区数相同，容量为：

$$
\text{容量}=\text{柱面数}\times\text{记录面数}
\times\text{每道扇区数}\times\text{每扇区数据字节数}
$$

若题目规定逻辑扇区按“同柱面内依次遍历盘面，各盘面内依次遍历扇区”编号，且各字段从 0 开始，设每道 $S$ 个扇区、$H$ 个记录面，逻辑扇区号为 $q$，则：

$$
c=\left\lfloor\frac{q}{HS}\right\rfloor,\qquad
h=\left\lfloor\frac{q}{S}\right\rfloor\bmod H,\qquad
s=q\bmod S
$$

编址顺序或起始编号改变时，需要相应调整。区域记录（ZBR）还允许外层环带每道包含更多扇区，不能对这种布局无条件套用“每道容量相同”的公式。

固定头磁盘为各磁道配置位置固定的磁头；活动头磁盘则通过磁头臂移动定位。按盘片能否取换，还可分为固定盘与可换盘。这是两组不同的分类。

### 磁盘的管理

#### 磁盘初始化

**低级格式化（物理格式化）** 建立扇区等物理组织，使控制器能够识别和读写。扇区通常包含头部、数据区域和尾部，其中保存标识、校验等控制信息；用户数据容量只计算数据区域。

磁盘通常在制造阶段已完成相应的物理格式化，并建立初始坏块和逻辑块映射信息。它与用户建立文件系统时的逻辑格式化不同。

#### 分区

**分区** 把磁盘划分为若干逻辑区域；**逻辑格式化（高级格式化）** 则在相应区域上建立文件系统，初始化目录和空闲空间管理等结构。

文件系统可以把若干扇区组织成块或簇作为分配单位，减小管理粒度过细的开销。非空文件最后一个分配单位可能没有填满，造成空间浪费；具体分配不能只按文件内容字节数判断。

分区表记录区域的位置和大小，传统 MBR 与 GPT 布局的区别见[操作系统引导](./os_intro.md#操作系统引导)。不要把分区、建立文件系统和建立物理扇区混为一谈。

#### 引导块

在传统引导模型中，固件保留小型引导代码，再把磁盘上的引导块载入执行，后者继续定位和加载操作系统。磁盘上的引导代码便于随系统更新，而不必把所有引导功能固定在 ROM 中。

MBR、分区引导扇区以及现代固件的完整流程，统一见[操作系统引导](./os_intro.md#操作系统引导)。本节只需区分 **用于启动的代码和信息** 与 **普通文件数据**。

#### 坏块

坏块处理的核心是避免继续使用不可靠的物理区域，常见方法有：

-   **软件标记**。文件系统记录坏块，分配空间时绕过。
-   **控制器重映射**。控制器维护坏块信息，用预留备用扇区替代损坏位置，向上层保持原逻辑块地址。

控制器重映射可以对操作系统透明，软件标记则由上层管理。是否能够恢复损坏前的数据，是另一问题，不能仅凭存在替代扇区就认为原数据一定完好。

### 磁盘调度算法

#### 磁盘的存取时间

一次机械磁盘访问的基本时间由寻道、旋转等待和数据传输构成：

$$
T_a=T_s+T_r+T_t
$$

-   **寻道时间 $T_s$**。移动磁头臂到目标柱面。在简化模型中，跨越 $n$ 条磁道、每条移动时间为 $m$、启动时间为 $s_0$ 时，$T_s=mn+s_0$。
-   **旋转延迟 $T_r$**。等待目标扇区到达磁头。若每秒转 $r$ 圈，随机位置下平均等待半圈，$\overline T_r=1/(2r)$。
-   **传输时间 $T_t$**。若每道数据量为 $N$ B，传输 $b$ B，则在连续传输模型中 $T_t=b/(rN)$。

转速按 rpm 给出时，要先除以 60。例如，5400 rpm 等于 90 转/秒，平均旋转延迟约为 5.56 ms。若给出目标扇区的具体角度，则应计算实际等待，不能直接取半圈。

寻道常是主要开销，磁盘调度重点减少磁头移动。若计算请求的完整响应时间，还需要按题目加入排队、控制器处理等时间。

#### 磁盘调度算法的比较

<center markdown="1">

| 算法 | 服务规则 | 主要特点 |
| :---: | :---: | :---: |
| FCFS | 按到达顺序服务 | 简单、公平，但可能频繁长距离移动 |
| SSTF | 每次选择距当前位置最近的请求 | 通常减少移动，但不保证总距离最小，动态请求下可能使远端请求饥饿 |
| SCAN | 沿当前方向服务，到物理端点后反向 | 类似电梯，可较好地照顾不同区域，但刚扫描过的位置可能等待较久 |
| C-SCAN | 只沿一个方向服务，到端点后返回另一端，回程不服务 | 提供循环式服务，等待分布较均匀，但返回有移动成本 |
| LOOK | 当前方向没有更远请求时就反向 | 避免为到物理端点而多走一段 |
| C-LOOK | 服务到本方向最远请求，再返回另一侧最远待处理请求，回程不服务 | 不要求到物理端点，仍需计入循环返回的移动 |

</center>

!!! tip "先明确方向、端点与返回计费"

    SCAN 与 LOOK、C-SCAN 与 C-LOOK 的转向位置不同。计算前先明确磁头初始位置和方向、磁道范围、回程是否服务，以及回程距离是否计入。

    下例严格区分四种扫描算法，计入循环返回距离，并在最后一个请求完成时停止统计；端点移动不是额外的用户请求。

设磁道范围为 0～200，初始位置为 100，请求顺序为 $55,58,39,18,90,160,150,38,184$，扫描方向先向磁道号增大的一侧。

<center markdown="1">

| 算法 | 从 100 开始的移动路径 | 总移动磁道数 | 平均寻道长度 |
| :---: | :---: | :---: | :---: |
| FCFS | 100 → 55 → 58 → 39 → 18 → 90 → 160 → 150 → 38 → 184 | 498 | 55.33 |
| SSTF | 100 → 90 → 58 → 55 → 39 → 38 → 18 → 150 → 160 → 184 | 248 | 27.56 |
| SCAN | 100 → 150 → 160 → 184 → 200 → 90 → 58 → 55 → 39 → 38 → 18 | 282 | 31.33 |
| C-SCAN | 100 → 150 → 160 → 184 → 200 → 0 → 18 → 38 → 39 → 55 → 58 → 90 | 390 | 43.33 |
| LOOK | 100 → 150 → 160 → 184 → 90 → 58 → 55 → 39 → 38 → 18 | 250 | 27.78 |
| C-LOOK | 100 → 150 → 160 → 184 → 18 → 38 → 39 → 55 → 58 → 90 | 322 | 35.78 |

</center>

总移动量是路径上相邻位置之差的绝对值之和，平均寻道长度的分母是 **9 个实际请求**，不计用于转向的端点。平均长度也不是平均时间；转换为时间还需按给定寻道模型处理。

**NStepSCAN 与 FSCAN**。

动态请求还可能导致 **磁臂黏着**：不断出现某一区域的新请求，使磁头长期停留。可以把当前处理集合与新到请求分开：

-   **NStepSCAN**。按到达顺序把请求分为最多 $N$ 项的子队列，依次用 SCAN 处理；扫描当前子队列时，新请求进入其他队列。$N=1$ 时，服务顺序退化为 FCFS。
-   **FSCAN**。使用两个队列：一个冻结为本轮服务队列，另一个收集新请求；本轮结束后交换角色。

冻结当前集合，使新请求不会无限延长这一轮扫描，改善热点请求对其他请求的影响。

#### 减少延迟时间的方法

读取一个扇区后，可能还要处理数据或切换磁头。如果下一逻辑扇区已经转过磁头，就需要额外等待。因此可以优化扇区的物理安排：

-   **交替编号**。同一磁道上，给逻辑相邻扇区留出物理间隔，使处理完成后下一扇区恰好接近磁头。
-   **错位命名**。不同盘面的相应扇区采用错位布局，为处理数据和切换磁头留出时间，减少跨盘面时错过扇区的等待。

这些方法优化的是布局与等待。间隔大小必须适应给定处理时间，不能认为逻辑编号越连续，物理访问就一定越快。

#### 提高磁盘 I/O 速度的方法

可以从减少实际访问次数、改善请求顺序和降低定位开销入手：

-   利用[磁盘高速缓存](#磁盘高速缓存)，让可复用的内容由主存满足。
-   按[调度规则](#磁盘调度算法的比较)调整服务顺序，减少寻道。
-   **提前读**。根据顺序访问趋势，读入当前块时预取后续块，减少将来的独立请求；预测错误则会产生多余传输。
-   **延迟写**。先修改内存缓冲中的数据，再在合适时机集中写回，合并多次更新。系统调用返回与数据已经写入磁盘不必是同一时刻。
-   **优化物理分布**。尽量让相关块位于同一或相邻磁道、同一柱面，并使用适当分配单位，减少定位次数。
-   **虚拟盘（RAM 盘）**。用内存提供一个供程序访问的磁盘式存储空间，适合临时数据。它本身是可见存储对象，磁盘缓存则是系统透明维护的副本。
-   **磁盘阵列 RAID**。利用多盘组织实现适当的并行访问，具体级别与冗余见[磁盘阵列](../CO/storage.md#磁盘阵列-raid)。

### 固态硬盘

#### 固态硬盘的特性

**固态硬盘（Solid State Drive，SSD）** 以闪存保存数据，通过 **闪存翻译层（Flash Translation Layer，FTL）** 把主机的逻辑块请求映射到实际闪存位置。

闪存按“块包含多个页”组织；此处的闪存页，与[虚拟内存中的页](./memory.md#基本分页存储管理)是不同概念。

<center markdown="1">

| 操作 | 基本单位 | 主要限制 |
| :---: | :---: | :---: |
| 读取 | 页 | 从目标位置取得数据 |
| 写入（编程） | 页 | 写入可用的已擦除位置，不能任意反复原地覆盖 |
| 擦除 | 块 | 整块恢复为可写状态，块内各页一起受影响 |

</center>

更新有效数据时，控制器需要安排可写位置，并在擦除旧块前保存其中仍有效的内容。这会带来数据迁移和擦除开销，随机写入通常比读取复杂；不能仅凭“无机械部件”就认为读写成本完全相同。

SSD 没有磁头寻道与盘片旋转等待，随机访问延迟较低，也具有抗震、低噪声等特点。其限制之一是擦写寿命有限，所以需要管理不同块的使用程度。

#### 磨损均衡

**磨损均衡（Wear Leveling）** 调整物理位置的使用，避免反复改写少数块，使它们过早达到擦写限度。

-   **动态磨损均衡**。分配写入位置时，优先选择擦写次数较少的空闲块，分散新写入。
-   **静态磨损均衡**。还主动迁移已经保存、长期不变的数据，让这些数据占用的块也参与整体使用调整，避免均衡仅发生在当前空闲区域。

在理想的均匀磨损模型中，介质累计可写入量可近似为“容量 $\times$ 每块允许的擦写次数”。这是帮助理解均衡效果的估算，实际还受数据迁移等额外写入影响，不能直接当作具体 SSD 的寿命承诺。
